## 2. 背景

### 2.1 項目初衷

[憲法 V2](DOC-01_OpenClaw_Bybit_Project_Constitution_项目宪法与根原则_V2.md) §1 將項目定義為：
在嚴格風險邊界、明確授權、完整審計與人工最終治理之下，以持續進化為核心目標運行的長周期
交易自主體。Operator 只設定硬邊界；邊界之內由 Agent 自主選擇品種、策略、參數、倉位與時機
（憲法 §4）。最終目標是長期、真實的淨收益；風控與治理是達成它的手段（[CLAUDE.md](../../CLAUDE.md) §二）。

憲法 §3.2 寫明系統不打純速度戰，並指出最容易寫成簡單規則的機會通常最擁擠。
§3.3 把優勢來源定為選擇、紀律、真實成本核算、異常時收縮，以及長期積累可重用的經驗。

### 2.3 問題陳述

以下為推論。

進化閉環缺少的是實驗引擎。原設計以實時 Paper 承擔實驗，每個假說以週計；該通道關閉後，
學習只能依靠 Demo 成交累積樣本，速度與樣本量都不足以支撐閉環。

憲法指定的優勢來源是選擇。檢驗選擇能力需要多年、跨數百品種的歷史；AE 自有的是有界保留的
近期行情，其實際保留深度未驗。成熟平台已持有的歷史資料與回測引擎，可把實驗時鐘由週縮短到
分鐘。這是融合的主要價值；減少本機歷史儲存負擔是次要收益。

> **2026-10-08 更正**：準確的說法是「缺少接入進化鏈、有足夠歷史、帶成本與統計閘門、且保真度經過驗證的
> 實驗服務」，不是缺少回測程式。「檢驗選擇需要跨數百品種」亦說過頭：廣度是部分選擇任務的需要，不是起點。

### 2.4 與 R8 候選的關係

2026-10-03 的候選由「減少本地長期行情負擔」觸發，分工為本機草擬、學習與交易，外部平台執行
歷史回測並回傳有限結果。本決策保留該分工的骨架，並依 §2.1 至 §2.3 重新確立理由、收窄可回傳
內容的用途、補上候選未涉及的訊號邊界與即時判斷。

## 4. 考慮過的選項

| 選項 | 主要收益 | 主要代價 | 判斷 |
|---|---|---|---|
| A 繼續全棧自建 | 控制自由最大 | 資料、回測、模型與運維持續佔用開發能力；實驗引擎仍缺 | 不採 |
| B 全部遷往平台雲端 | 最大程度利用現成平台 | 交易憑證與執行交給外部；平台可隨時終止服務且不負交易損失責任；既有治理須重建；牴觸根原則 14 | 不採 |
| C 本機以 LEAN 取代 Rust 核心 | 重用通用引擎 | 核心遷移工程巨大；本機歷史資料負擔仍在；既有風控與恢復能力須重新驗證 | 不作本輪主線 |
| D AE 核心加平台實驗台 | 保留控制權，補上實驗引擎，卸下歷史研究負擔 | 須處理策略一致性、資料條款與結果接入 | **採納** |

採納 D 的理由有三。第一，缺口在實驗引擎，D 直接補它，不動已可用的執行與治理資產。
第二，B 與 C 都要重建或重驗資金安全相關能力，而這些能力與當前缺口無關。
第三，D 的失敗代價有界：平台不適配時可停止融合，本機運行不受影響。

### 5.3 設計原則

後續 R8 單元以下列原則為準。P1 至 P8 概括 Operator 接受的採納版中的設計判斷，條文措辭由記錄者整理；
細節可在各階段准入時修訂，修訂不得違反 §9。

> **2026-10-09 修訂**：P1 依 AM1、P2 依 AM12、P3 依 AM4 修改；P5 依 AM11 補充。內容見[修訂一](2026-10-08--r8-amendment-1-first-loop-on-native-replay.md) §4。

**P1 兩級實驗台。** 本機一級以開源 LEAN 加自有或交易所公開資料運行，可取逐樣本特徵，
不依賴外部付費服務。雲端一級做長歷史、寬 universe 的確認，只回傳摘要。雲端停用時只停新研究。

**P2 兩個時鐘。** 可回測的策略、參數與選擇規則走實驗台。語言模型與 Agent 的即時判斷不可
回測，因為模型已接觸過歷史；它只能在前向 shadow 中對基線逐筆計分。後者的驗收問題固定為：
加入 AI 的版本，是否優於相同資料與執行條件下不用 AI 的版本。

**P3 先校準儀器。** 實驗台的結論在被信任之前，須先以 AE 的真實成交校準：選取有真實 Demo
成交的既有策略，在實驗台重放同一時間窗，結果須在可解釋範圍內重現已實現的成本後損益。
未通過校準的實驗台，其正收益結論不予採信。

**P4 統計治理前置。** 假說預登記、試驗計數、時間切分與 holdout 消耗帳在提交實驗前強制執行，
沿用既有統計閘門。實驗成本下降會放大多重檢驗風險，故此項不得後補。

**P5 成本三層。** 交易淨收益；策略貢獻，即再扣除推理與監控成本；系統經營，即再納入研究、
資料與硬體成本。每項成本只扣一次。

**P6 單一意圖入口。** Rust 上游只接受帶 Decision Lease 的意圖。Rust 原生策略、共用訊號套件
與 Agent 決策同為意圖來源，適用同一套審核。此原則的落地待 §5.5 的 ADR。

**P7 故障隔離。** 研究與交易是兩個獨立迴圈。平台不可用、逾時或帳戶中止，不得阻塞交易、
風控、對帳或既有策略的運行。

**P8 以閉環為驗收單位。** 進度以「閉環走完一圈」衡量；報告數、測試數與介面完成度不是進度。

### 5.4 資料邊界

依平台條款（§16），平台資料只可在平台代管環境內使用，不得以任何方式或數量匯出，
其明列的間接途徑包括日誌、圖表、Object Store、網路請求、API 與 MCP。可離開平台的只有
自有源碼，以及自有回測與實盤的摘要結果，即績效統計、權益曲線與自有訂單歷史。
使用者對自動化工具的一切行為負責。

> **2026-10-08 更正**：上段漏列一條合法途徑。平台另有付費下載（條款所稱 CLI API Access and Data Agreement）。
> 依平台的[資料授權說明](https://www.quantconnect.com/docs/v2/cloud-platform/datasets/licensing)，下載資料限組織內部
> LEAN 使用，不得轉換格式或再分發，因此不能作為 Rust 回放的資料來源。本路線預設不採購下載授權。

據此規定：

1. 上行內容限於源碼、參數、標的與時間範圍，上傳前經靜態檢查，拒絕任何輸出行情值的寫法。
2. 下行只接收白名單欄位。
3. 逐樣本的特徵與標籤不從平台取回；需要逐樣本資料的模型訓練，只使用 AE 自有資料或向交易所
   按需取得的資料。
4. 上述邊界由程式強制執行，不依賴約定或 Agent 的自律。

> **2026-10-09 修訂**：第 1 點依[修訂一](2026-10-08--r8-amendment-1-first-loop-on-native-replay.md)的 AM5 修改：平台上只執行已審核的固定模板，靜態檢查降為輔助。

### 5.5 訊號邊界與過渡規則

現行架構中，策略以 Rust 實作；[ADR-0051](../adr/0051-registry-authorized-advisory-model-serving.md)
限定模型輸出為 `NO_OP | VETO | SIZE_DOWN`，不得發起進場。在此約束下，Agent 進化出的每個新策略
都需要人工改寫為 Rust。由此推論：憲法 §1 所稱「自主孵化新策略」在現行約束下難以達成。

Operator 同意另立 ADR 處理此事；ADR 的內容由其自身的審查流程決定。記錄者建議它涵蓋：
訊號計算可由兩端共用、版本固定的純計算套件承擔；套件只輸出提案，不得下單，不得以自有模擬
持倉取代權威帳戶狀態，不得持有風控配置或啟用權；最終由 Rust 判斷。並建議一併處理 Python Agent
產生的意圖如何進入 Rust 的問題。

過渡規則：該 ADR 被接受之前，ADR-0051 與現行硬邊界照舊；任何可發起進場的非 Rust 訊號來源
不得接入交易路徑。

## 8. 階段與驗收

下列為方向性順序，不是派工。每一階段開始前，由 PM 依現行規則重新准入。

> **2026-10-09 修訂**：本節的階段由[修訂一](2026-10-08--r8-amendment-1-first-loop-on-native-replay.md) §5 的階段表取代（涉及 AM2、AM3、AM8、AM9、AM10）。第一圈改用既有 Rust 回放，且不含 Demo 採用。

無法解釋，或費用超出批准上限時，縮小或停止融合。

**階段 2：訊號邊界 ADR。** 依 §5.5 起草，並依既有 ADR 審查流程決定。

採用只發生在 Demo，並經 GovernanceHub 與 Decision Lease。放行條件是閉環無人手走完，
且結果可重建。

**階段 4：意圖來源介面。** 第一個新策略候選通過階段 3 的統計閘門之後才建置，

## 11. 成效判定

融合是否值得，從三方面判定，不看程式行數或 Agent 數量。

- 工程效率：從提出假說到取得可判斷結果的時間與費用；本機歷史維護負擔是否下降。
- 功能真實性：結果是否完整可追溯；兩端策略是否一致；採用是否真的改變了被允許的決策。
- 經濟有效性：扣除新增的平台與 AI 成本後，策略或決策是否仍有價值；加入 AI 的版本是否優於
  不用 AI 的版本。
