## 2. 背景

### 2.1 對抗審核

2026-10-06 的獨立審核判定：保留有界融合方向；工程方案須修改；最優性尚未建立。
它提出十項發現，前五項為「若照原文落實，可能無法合法通過驗收或產生不可靠結論」，後五項損害效率與可驗收性。

| 發現 | 要點 |
|---|---|
| F1 | 自主 Demo 採用沒有對應到任何現行合法的消費路徑 |
| F2 | 重現 Demo 損益不能校準實盤，也不能替代策略一致性 |
| F3 | 任意程式加靜態掃描，不能保證平台資料不外流 |
| F4 | 候選身份、摘要證據與逐事件驗收之間缺少可實作的契約 |
| F5 | 接上真實引擎前對證據注入的阻擋被寫成可選 |
| F6 | 「選擇」沒有操作性定義，資料廣度被當成前提 |
| F7 | 流程自動化、第二代學習與 REJECT 的驗收沒有分開 |
| F8 | 前置架構過重，停做清單尚未形成真正的減法 |
| F9 | 預算上限沒有回答總成本與經濟回收 |
| F10 | 「不可回測」與「超越人類」寫得過滿 |

### 2.2 補充意見

同一審核者其後的補充意見支持把既有 Rust 回放升為第一圈優先盤點與驗證的候選，同時指出：
回放的成交與資料假設需要有界驗證；不能重現 Demo 虧損不等於實驗台必然樂觀，應分兩步驗證；
S2 應維持正式需求並補驗收定義；平台的付費下載資料不能餵給 Rust 回放；
改用回放並調整階段順序屬於實質修訂，應另立決策。

## 3. 融合方向內的方案比較

R8 §4 比較的是四條大路線。下表比較同一融合方向內、第一圈可用的做法。
比較的是自現在起到第一個合格裁決的增量成本；已投入的 Rust 工程是沉沒成本，不計入。

| 方案 | 第一圈需新增的工作 | 已知限制 | 判斷 |
|---|---|---|---|
| 甲 既有 Rust 回放加公開 K 線 | 四項修補（估 2.5–4.5 個工程日），另加一次對帳 | 一分鐘、吃單、沙盒級證據；五月的偏差未結案 | **首選候選，有條件** |
| 乙 本機開源 LEAN 加另有權利的資料 | 策略移植為 LEAN、逐事件一致性、資料轉換 | 無平台月費；移植成本未量測 | 回放不適用時的本機備選 |
| 丙 QC 雲端固定模板 | 同乙的移植與一致性，另加帳戶准入與上下行管制 | 受平台條款約束；廣度與報價歷史是其所長 | 依 AM2 進場，不在第一圈關鍵路徑 |
| 丁 不新增工作，等待 Demo 樣本 | 無 | 不產生裁決 | 不採 |

甲的估計來自差距盤點，未經量測；乙與丙的成本沒有估計。因此本表支持「先驗證甲」，不支持「甲是全局最優」。

## 4. 修訂內容

**AM1 第一圈的實驗引擎。** 第一圈以既有 Rust 回放為首選實驗引擎。P1 中「本機一級以開源 LEAN 加自有或交易所公開資料運行」
改為「本機一級以既有 Rust 回放為先；開源 LEAN 是回放不適用時的本機備選」。
採用條件是 §5 階段 1 的修補完成且階段 2 的驗證通過；任一不成立，回到 §3 重新比較，不延長修補。
理由：回放直接執行 production 的策略實作，省去移植與其一致性成本；實跑已證明路徑可執行。

**AM2 平台進場條件。** D2 的意旨不變：成熟平台仍是 Agent 實驗台的組成部分。平台（本機 LEAN 與 QC 雲端）進場的判準是：
對一個具體的研究問題，它能以更低的增量總成本、更快地產生合格裁決。標的數量多寡本身不是判準。
目前已知會觸發的情形：小時級、日線級或橫截面研究（G4）；需要早於本機記錄器的報價或盤口資料；
股票與 ETF 研究；回放的保真度無法以小修達到所需程度。平台的帳戶准入改為在第一次觸發時執行；
資料目錄所列的覆蓋數不等於逐時點的可交易性，准入時須按指定品種與期間驗收。

**AM3 權限矩陣。** 第一圈在研究沙盒與前向 shadow 內完成，不包含任何在 Demo 生效的採用。
R8 §8 階段 3 中「採用只發生在 Demo，並經 GovernanceHub 與 Decision Lease」一句刪去。

| 候選動作 | 現行依據 | 所需條件 | 第一圈 |
|---|---|---|---|
| 在研究沙盒內提出假說、跑實驗、寫研究證據 | 無交易效果；受統計治理與預算約束 | 單元准入 | 包含 |
| 對既有策略的風險增加型進場輸出 `NO_OP`、`VETO`、`SIZE_DOWN`，只記錄不生效 | [ADR-0051](../adr/0051-registry-authorized-advisory-model-serving.md) A3 的動作集合 | 單元准入 | 包含 |
| 上述輸出在 Demo 生效 | ADR-0051：須有登記授權與 Rust 消費端的相符確認；[TODO](../../TODO.md) §0：每個 Demo 效果須有當前、明確範圍的授權 | 兩者皆具備 | 不包含（階段 5） |
| 調整既有策略的參數 | [ADR-0034](../adr/0034-decision-lease-layered-approval-lal.md)：LAL 1 只適用 Stage 4 且 30 日穩定 | 現行條件未滿足；須走 Operator 手動路徑或另立窄授權修訂 | 不包含 |

| 新策略族上線 | ADR-0034：LAL 3，其自動資格依該 ADR 的 Level 規定；R8 D5 的訊號邊界 ADR | 預設須 Operator 批准 | 不包含 |

> 選擇器的輸出在那裡不改變任何真實進場。在隔離回放內則相反：選擇器的 `VETO` 與 `SIZE_DOWN` 必須改變回放中的

**AM4 儀器驗證。** P3 與 E06 改為三層。

1. 事件級檢查：以本機 fixture 檢查資料何時可知與何時可成交、指標預熱、狀態轉移、風控前的意圖。
2. Demo 對帳，分兩步。第一步，把已發生的 Demo 訂單、成交、費用與資金事件餵入記帳重建，
   按事前容差重現其損益；不符即否定該記帳鏈。第二步，給同一時間窗的行情與同一策略設定，由回放自行生成成交；
   對齊資料與設定後，仍有超出事前容差且無法解釋的有利偏差，才否定回放在此用途的可信度。
3. 獨立期間的成本壓力測試。

作為儀器驗證對象的策略不需要有優勢。
容差事前固定。用於調整模型的時間窗與用於驗證的時間窗分開。依對抗審核引用的交易所說明，Demo 訂單不進入真實訂單簿，
故通過 Demo 對帳不代表實盤成交的真實度；本提議未獨立核實該說明。實盤成交模型在有合法的實盤觀察之前標為未校準，採保守範圍。

**AM5 平台上行限制。** 本項只在 AM2 觸發後適用。平台上只執行經審核、相依版本固定的模板；
Agent 在受限規格內選擇參數與假說；結果由固定的計算程式輸出，限制欄位、數量與精度。
靜態檢查保留為輔助手段，不作為「資料不會外流」的保證。需要任意新程式時另行審查，並另行設計隔離與輸出管制。
本項取代 §5.4 第 1 點與 E04。Agent 仍自主決定研究什麼。

**AM6 實驗身份與證據通道。** E01 擴充：一次實驗的身份除候選內容外，還包括引擎與相依版本、資料來源與覆蓋、
時間語義、成本與成交模型、隨機種子（如有）與試驗譜系。證據分兩條通道：本機自有或另有合法權利的資料，用於逐事件驗證；
平台資料的檢查與統計留在平台內，只取回允許的摘要、任務身份與環境版本，不稱本機已獨立重算。
E14 的適用範圍擴充：除訊號邊界 ADR 之後的共用套件外，任何把平台結果用於既有 Rust 策略的候選，也須有窄範圍的語義一致性證據。Object Store 不作為結果通道。

**AM7 證據注入的阻擋。** 任何把真實引擎接到現有回測入口的單元，必須先確保未經統計閘門的結果不能成為受信任的學習證據；
或使用隔離的新入口，並證明它不觸發既有的自動注入路徑。這是硬要求，取代 §6 末段的「建議」。
它約束的是證據平面，不表示該注入本身會下單。

**AM8 「選擇」的操作性定義與第一圈任務。** 選擇分為五類任務：選品種、選策略、選時點、停手、配置。
第一圈只做一類：停手，即判斷何時不做。範圍固定為一個策略族、少量標的、一分鐘線、吃單。
盤點顯示目前可被保守界定的對象是 ma_crossover；網格依賴掛單，受 G2 影響，暫不適用。這是工程篩選，不表示該策略有優勢。

對照分三組：固定策略全做、簡單的確定性停手規則、Agent 或模型的停手選擇器。三組使用同一資料、同一風險預算、同一成本口徑，
並各自重跑回放，不以同一份基線成交清單事後相減。標的清單使用當時可得的資料與已知時間，不以今日清單回填。
全部搜尋、重試與人工調整記入同一本試驗帳；holdout 不反覆向生成器揭示細節。

**AM9 驗收分為三個。** 本項細化 D8，不改變其意旨。

- 流程驗收：流程自動完成，涵蓋拒絕、預算耗盡與重啟恢復。
- 學習驗收：前一代的結果確實改變了下一個合法候選或研究選擇，版本與理由可追。只排程重跑、不消費前代結果不算通過。
- 增益驗收：相對基線有成本後價值；否則保留原策略。

全程 REJECT 可以是工程成功，但不得據此聲稱選擇能力或收益提高。採用分支才進入 Stage 0R 與 Demo；拒絕分支以知識回流結束，
不為走完閉環而強迫成交。在只有公開 K 線的資料層，增益驗收只接受相對比較，不接受「絕對淨收益為正」。

**AM10 階段順序與減法。** E02 改為先建一個實際使用的後端；第二個後端確有用途時才抽出共用介面。
訊號邊界 ADR 照常起草，但不是第一圈的前置。E11 的零付費驗收須指明不依賴付費帳戶的啟動方式。
§7 停做清單的每一項須對應具名的停止項與觸發條件；先停止新增範圍，不刪資料。階段見 §5。

**AM11 成本口徑。** 補充 P5 與 E09。每一輪記錄三個量：增量成本，即增量現金、工程工時乘以明示的影子時薪、維護成本之和；
到第一個可重建裁決的時間；每個有效裁決的成本。REJECT 是有效裁決；以相近參數灌大裁決數不算效率。
定額月租與增量研究成本分開記，不因月費已付而放寬試驗預算，也不對每個任務重複攤入整月費用。
投入上限到期時可回報 INCONCLUSIVE；不把樣本不足改判為通過，不自動續建。

**AM12 即時判斷與 S2。** P2 的理由句改為：無法排除模型接觸過歷史的測試，只作功能與失敗分析；增益以前向證據為準。
前向 shadow 固定模型、提示與版本，並先與可重現的簡單程式基線比較。它不以同一事件的不同建議相減作為增益；
基線與候選各自維護可重建的假設組合與資本約束，未成交的部分標為模擬。E13 所記錄的逐事件差值因此只作診斷，不作增益依據。
S2 維持正式需求，狀態記為「驗收基準待定」。基準至少事前固定：對標的人類或人類策略類別、雙方可用的資料與決策時間、
資本與風險、費用與 AI 運行成本、觀察期與市場狀態覆蓋、主指標與硬限制。勝過選定的基線不等於勝過所有人類；
有限的第一圈只驗證子能力，不得稱已完成此項需求。
