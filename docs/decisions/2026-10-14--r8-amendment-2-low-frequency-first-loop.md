## 2. 背景

### 2.1 第一圈原任務與盈利的距離

修訂一把第一圈定為 ma_crossover 一分鐘線、吃單的「停手」三組對照（AM8），並寫明這是工程篩選，不表示該策略有優勢。

數值只屬其原觀察期。

以下為推論，未經本路線實測。回放對每筆吃單計入 5.5 bps 手續費加 5 bps 不利滑點（修訂一 §2.3），一次來回約 21 bps，
在一分鐘級的價格變動中佔比很高。停手只會減少交易，最多讓一個沒有成本後優勢的策略少虧，不會使它轉為盈利。
持有期較長、換手較少的假說，成本佔預期收益的比例較低，較可能留下成本後優勢。

## 4. 修訂內容

**N1 第一圈的任務。** 第一圈改為預登記的低頻假說搜尋：以 1 小時、4 小時或日線為主要決策週期，對少量假說逐一作成本後裁決。
AM8 對「選擇」的五類操作性定義不變；第一圈不再限於「停手」，也不再固定於 ma_crossover。

- 每個假說在登記時寫明經濟理由、預期持有期與換手率，並以 N3 的悲觀成本估算成本佔比。
- 假說、標的範圍與期間在階段 2 結束前預登記，列入階段 3 的派工指令，由 Operator 覆閱。
- AM8 對照實驗的要求中，下列各項照舊適用：同一資料與成本口徑；標的清單使用當時可得的資料與已知時間，不以今日清單回填；
  全部搜尋、重試與人工調整記入同一本試驗帳；holdout 不反覆向生成器揭示細節。
- 原「停手」三組對照與階段 1 的選擇器注入點保留，改為之後可選的研究題目。

**N2 第一圈的實驗引擎。** AM1 改為：第一圈的實驗引擎是本機低頻研究工具；Rust 回放保留，用於候選改寫成 Rust 之後的一致性核對（N7）。
選型以一個工作日的查核決定：不使用付費平台帳戶，以本機開源 LEAN 對一個假說、用 N3 取得的資料跑通，並確認資金費能計入。
一日內跑通即採乙；否則採戊，不延長查核。查核結果記入階段 2 的交付記錄。

- 所採方案必須能在沒有付費平台帳戶的情況下啟動（E11）。
- 所採方案同樣適用 E01（經 AM6 擴充的實驗身份）與 E07（成交與成本模型）。

**N3 研究資料與成本。**

1. 研究資料直接向 Bybit 公開介面取得：K 線、資金費歷史，需要時含持倉量。取得的資料存為本機檔案，記錄雜湊與取數時間。
   研究不讀取、也不寫入 Linux 資料庫。本項只約束研究資料的來源，不涉及交易、風控或對帳。
2. 取數是對外請求。標的、期間與端點在派工指令中列明，經 Operator 同意後才執行；只用公開端點，不使用帳戶或金鑰。
3. 標的清單依上市日期按時點取用。已下架品種若無法取得，記為倖存者偏差的限制；這是 N6 平台用途之一。
4. 成本偏悲觀：吃單手續費依現行費率等級雙邊計入；滑點設基準值並作壓力測試（即 AM4 第三層）；資金費以歷史實際費率在結算點計入。
   修訂一 2026-10-09 的裁決（資金費結算不納入階段 1）只適用於回放的四項修補。低頻持倉必然跨越結算點，第一圈的研究工具必須計入資金費。
5. 統計治理沿用 P4 與 E08：假說預登記、試驗計數、時間切分、holdout 使用帳，並作多重檢驗調整。可沿用倉庫既有的統計工具。

**N4 儀器驗證。** 第二層改為 Demo 前向對照是 Operator 的決定；以下條文是記錄者的展開，未經 Operator 確認。AM4 的三層改為：

1. 事件級檢查：對所採的研究工具，以本機構造的資料檢查資料何時可知與何時可成交（以收盤後才可知的資料決策，於下一根開盤成交）、
   指標預熱、資金費結算時點與狀態轉移。
2. Demo 前向對照，取代原第二層。候選在 Demo 運行時，以同一時間窗的行情與相同設定，比對研究工具（以及已支援時的回放）的預測與 Demo 實際結果。
   容差事前固定；有超出容差且無法解釋的有利偏差，即否定該工具在此用途的可信度。
   前向窗的成交與資金流水以交易所端的記錄核對（由 Operator 匯出，或經另行授權的唯讀途徑），不以資料庫為唯一來源。
3. 成本壓力測試：照舊，併入 N3 第 4 點。

原第二層的兩步（以資料庫內的歷史 Demo 記錄重建損益；給同一歷史窗由回放自行生成成交）不再是第一圈的前置。
修訂一引述的「Demo 訂單不進入真實訂單簿」仍未核實；通過 Demo 前向對照，不代表實盤成交的真實度。

這一改動的後果是：P3 與 E06 要求的校準，現在落在階段 5，晚於階段 3 的裁決。因此階段 3 的一切裁決都標為「未經 Demo 校準」，
只能支持「改寫成 Rust 並進入 Demo 前向測試」的決定，不能支持採用或任何對外的收益主張。

**N5 研究階段的「候選成立」。** AM9 末句規定，只有公開 K 線時，增益驗收只接受相對比較，不接受「絕對淨收益為正」；
其意旨是公開 K 線不足以證明實際盈利。第一圈的研究資料全部來自公開介面（N3），而下列門檻含「成本後淨結果為正」這一絕對條件，
因此本項確實改變了 AM9 末句在研究階段的適用。本項保留其意旨：「為正」只是記為候選的必要條件之一，不構成 AM9 的增益驗收；
增益驗收仍待 Demo 前向證據。一個假說在 holdout 上同時滿足下列各項，才記為「候選成立」：

- 在悲觀成本下，成本後淨結果為正，且優於預登記的簡單基準（例如不交易，以及暴露相近的被動持有）；
- 通過多重檢驗調整；
- 報告市場貝塔暴露及扣除後的結果；多頭行情佔主導的結果依 Alpha 證據治理標為 regime-bet，只作學習用途。

「候選成立」只表示值得改寫成 Rust 並進入 Demo 前向測試，且如 N4 所述標為「未經 Demo 校準」。它不是晉級證據，也不得據此宣稱已能盈利。
全部假說不成立是有效裁決（REJECT）。

**N6 平台後置。** Operator 決定：本機開發與平台配套都完成之後，才有限使用 QC。

AM2 原把「小時級、日線級或橫截面研究」列為平台進場的已知觸發情形，並規定帳戶准入在第一次觸發時執行。
第一圈改為低頻研究（N1）後，這個觸發在階段 2 就會成立。依 Operator 的決定，AM2 中「帳戶准入在第一次觸發時執行」一句，對 QC 雲端改為：
帳戶准入在下列清單全部完成之後才執行。N2 在本機使用開源 LEAN，不使用付費平台帳戶，不屬帳戶准入。
AM2 的判準本身（對具體研究問題，能以更低的增量總成本、更快地產生合格裁決）不變，在決定是否使用 QC 時照舊適用。

以下清單是記錄者對「完成」的展開，未經 Operator 確認；全部滿足後，由 Operator 授權帳戶與支出。

本機：

1. 階段 2 驗收通過。
2. 至少完成一輪本機研究圈並產出裁決（階段 3），結果可重建。

平台配套：

3. 預先列明只有平台能回答的問題，限於：本機資料涵蓋期之前的長歷史、已下架品種、以第二個引擎確認本機的候選。

**N7 引擎與回放的低頻支援。** 依 H1–H4，低頻候選要在 Demo 運行，須先補引擎與回放的支援。

- 只在至少一個假說「候選成立」之後才建置，範圍以該候選所需為限。
- 這屬 Rust 源碼變更，觸及行情與策略熱路徑，依現行治理需要獨立的代碼審查與測試驗證，以及事實觸發的其他審查。
- 改寫後的 Rust 策略，以同一份資料與本機研究工具逐事件比對（AM6 的一致性要求）。
- 新策略族在 Demo 運行，依 AM3 與 ADR-0034 須經 Operator 批准。
