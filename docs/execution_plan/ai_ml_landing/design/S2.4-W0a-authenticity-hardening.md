## 0. Problem framing and honest boundary

W0a made S2.0's production observer-bootstrap apply **reachable** behind an authority gate
(`_apply_production_observer_bootstrap`, steps 1–9). Codex posted **5 P1 findings** that were
harmless while production apply was unconditionally deferred but are newly exploitable now that the
`APPLIED` branch is reachable. All 5 are fixable **inside the W0a package** by verifying a
**trusted-host-SIGNED apply attestation** — consistent with the Typed Authority Matrix: *source may
verify a signature's integrity + trust-root binding; it must NOT assert that the runtime apply
actually happened.* Full runtime-apply authenticity remains the out-of-band closure / S2.0 EFFECT
verification.

W0a-package paths that may change: the S2.0 module, its result schema, the Registry authority string,
and its tests. The S1 trusted-host module (`agent_governance_aiml_trusted_host.py`) is **read-only
reuse** (import only). No `route_task` effect node, no closure effect binding, no production contact.

Root cause common to all five: the `APPLIED` unlock trusted **caller-controlled inputs** (a bare
`driver.evidence_class` attribute, a caller `now`, an unbound verifier digest) instead of a
**signed, independently verifiable** attestation bound to the exact intent, the applied catalog
digest, and a trusted-host timestamp.

## 1. Trusted-host apply attestation (resolves T1 + T5 + T2 together)

### 1.1 New signed artifact `pg_observer_bootstrap_apply_attestation_v1`

The production driver must return a **signed apply attestation** — a canonical object plus a raw
SSHSIG — that the module verifies before emitting `APPLIED`. It reuses the §9.1 physical trust root
(the same Ed25519 key as S0.3/S1, fingerprint `SHA256:uGJ9veN7PoE6BBgfsSP2aiMndrwgbt7o/7/YfdzNzCQ`,
public key `agent_governance_aiml_trusted_host.S1_TRUSTED_TARGET_HOST_PUBLIC_KEY`) under a **distinct
apply-attestation identity + namespace** for domain separation from the pre-approval operator
authorization.

New module constants (in `agent_governance_pg_observer_bootstrap.py`):

```

ATTESTOR_IDENTITY                = "aiml-s2-observer-bootstrap-attestor-v1"
ATTESTOR_FINGERPRINT             = trusted.EXPECTED_S1_TARGET_HOST_SIGNER_FINGERPRINT   # §9.1 trust root
ATTESTOR_PUBLIC_KEY              = trusted.S1_TRUSTED_TARGET_HOST_PUBLIC_KEY            # §9.1 trust root

ATTESTATION_FIELDS = frozenset({
    "schema_version", "attestor_identity", "attestor_fingerprint", "algorithm",
    "signature_namespace", "intent_id", "intent_digest", "source_head", "target_host",
```

The signed object shape:

```json
{
  "schema_version": "pg_observer_bootstrap_apply_attestation_v1",
  "attestor_identity": "aiml-s2-observer-bootstrap-attestor-v1",
  "attestor_fingerprint": "SHA256:uGJ9veN7PoE6BBgfsSP2aiMndrwgbt7o/7/YfdzNzCQ",
  "algorithm": "SSH-ED25519",
  "signature_namespace": "arcane-equilibrium-aiml-s2-observer-bootstrap-apply",
  "intent_id": "sha256:...",                 // == intent.intent_id
  "intent_digest": "sha256:...",             // == intent.self_digest
  "source_head": "<40-hex>",                 // == intent.source_head
  "target_host": "<attested Linux host>",    // == intent.target_host
  "applier_node_id": "<applier>",            // == intent.applier_node_id
  "postcheck_node_id": "<verifier>",         // == intent.postcheck_node_id
  "applied_grant_set_digest": "sha256:...",  // the catalog state produced by the apply (!= pre)
  "reobserved_digest": "sha256:...",         // the DISTINCT verifier reobservation; MUST == applied (T2)
  "evidence_class": "PLATFORM_ATTESTED",
  "trusted_host_time": "2026-..Z",           // the trusted-host clock (T5 anchor)
  "attestation_expires_at": "2026-..Z",      // trusted_host_time + bounded TTL
  "attestation_digest": "sha256:..."         // canonical_digest over all fields except attestation_digest
}
```

The SSHSIG (raw ASCII-armored bytes, ≤16 KiB) is computed over `canonical_bytes(attestation)` (the
full object including `attestation_digest`), mirroring the existing operator-authorization signing
convention (`canonical_bytes(authorization)` in `validate_operator_authorization`).

**Why a separate identity/namespace, not the operator's.** The operator authorization
(`aiml-s2-observer-bootstrap-operator-v1` / `arcane-equilibrium-aiml-s2-observer-bootstrap`) is a
*pre-approval* of the exact intent (15-min TTL, signed before apply). The apply attestation is
*post-apply evidence* that binds the actually-observed `applied_grant_set_digest` and a real
`trusted_host_time` — knowable only after the apply runs. Reusing one namespace would let a
pre-approval SSHSIG be replayed as an attestation. `ssh-keygen -Y verify` binds the namespace, so the
distinct namespace makes the two artifacts non-interchangeable while reusing one physical key
(exactly the §9.1 domain-separation pattern that gives S0.3 and S1 separate namespaces on one key).

### 1.2 Builder (used by the driver / tests to produce the object before signing)

`build_apply_attestation(*, intent, applied_grant_set_digest, reobserved_digest, trusted_host_time, ttl_seconds=EVIDENCE_TTL_SECONDS) -> dict`
(analogue of `build_operator_authorization`):

- assert `applied_grant_set_digest` and `reobserved_digest` are `sha256:` digests and **equal** (T2 at build);
- populate all `ATTESTATION_FIELDS` from `intent` (id/digest/source_head/target_host/applier/postcheck) and the args;
- `evidence_class = "PLATFORM_ATTESTED"`; `attestation_expires_at = trusted_host_time + ttl_seconds`;
- `attestation["attestation_digest"] = canonical_digest(attestation without attestation_digest)`;
- return the object (the caller signs `canonical_bytes(attestation)`).

### 1.3 Apply-time verifier (the gate that unlocks `APPLIED`)

`validate_apply_attestation(attestation, signature, *, intent, operator_authorization, applied_grant_set_digest) -> list[str]`
returns `[]` iff **all** of the following hold (each maps to a P1):

1. **Structure** — `isinstance(attestation, dict)`; `set(attestation) == ATTESTATION_FIELDS`;
   `signature` is `bytes`; `schema_version / attestor_identity / attestor_fingerprint / algorithm /
   signature_namespace / evidence_class` equal their const expectations;
   `attestation_digest == canonical_digest(attestation without attestation_digest)`.
2. **Intent binding (T1 scope)** — `intent_id / intent_digest / source_head / target_host /
   applier_node_id / postcheck_node_id` equal the exact intent; `intent.self_digest ==
   intent_self_digest(intent)`.
3. **Verifier digest bound (T2)** — `reobserved_digest == applied_grant_set_digest ==
   attestation.applied_grant_set_digest == <runtime applied digest>` and `applied != pre` (state
   changed). A divergent verifier observation ⇒ error ⇒ no `APPLIED`.
4. **Trust-root binding (T1)** — `hmac.compare_digest(trusted.ssh_public_key_fingerprint(ATTESTOR_PUBLIC_KEY), ATTESTOR_FINGERPRINT)`.
5. **Signature (T1)** — `trusted._verify_ssh_signature(canonical_bytes(attestation), bytes(signature),
   public_key=ATTESTOR_PUBLIC_KEY, identity=ATTESTOR_IDENTITY, namespace=APPLY_ATTESTATION_NAMESPACE)`
   must return `True`. **A bare `evidence_class` attribute is no longer sufficient.**
6. **Trusted-clock freshness (T5)** — parse `trusted_host_time`; require
   - `intent.created_at <= trusted_host_time < intent.expires_at` (inside the intent window),
   - `operator_authorization.issued_at <= trusted_host_time < operator_authorization.expires_at` (inside the pre-approval window),
   - `trusted_host_time < attestation_expires_at` and `attestation_expires_at - trusted_host_time <= MAX_APPLY_ATTESTATION_TTL`.
   Freshness is derived from the **signed** timestamp, never the caller `now`.

**Why this defeats the T5 replay.** The caller `now` remains a *necessary-not-sufficient* first
filter (a caller who supplies a future/expired `now` is rejected earlier and can only ever tighten,
never loosen). But `APPLIED` is unlocked only when the **signed** `trusted_host_time` — which the
attacker cannot forge — is inside both signed windows. Replaying an expired intent by passing a
historical `now` inside the original validity window fails, because the driver's real
`trusted_host_time` at actual apply time is `>= intent.expires_at`, so check (6) fails and the branch
fails closed.

### 1.4 `ObserverBootstrapProductionDriver` protocol amendment

Add one fixed-operation method (no raw SQL/DSN/secret; opaque object only):

```
def signed_apply_attestation(self, *, intent, applied_grant_set_digest, reobserved_digest) -> dict:
    """Return {"attestation": <pg_observer_bootstrap_apply_attestation_v1 object>,
               "signature": <raw ASCII-armored SSHSIG bytes>}.

    The attestation binds the exact intent identity, the applied catalog digest, the distinct
    verifier's reobserved digest (== applied), evidence_class=PLATFORM_ATTESTED, and a
    trusted-host-signed timestamp; it is signed by the §9.1 trust-root key family under the
    observer-bootstrap-apply namespace. Only a real trusted host that holds the off-repo private
    key can produce a signature that verifies against the pinned ATTESTOR_PUBLIC_KEY."""
```

`evidence_class: str` is retained as a **first-filter** attribute (kept so a
simulation/disposable driver reporting `LOCAL_REPRODUCIBLE`/`STRUCTURAL_ONLY` is rejected before any
attestation call), but it is no longer the unlock; the signed attestation is.

### 1.5 `_apply_production_observer_bootstrap` steps 6–9 rewrite (driver-present region)

```
6.  observer_role_present must be ABSENT           -> else PENDING (unchanged)
6b. pre = observe_acl_state
7.  role_created = True; create_read_only_observer(grant_set)
7b. applied = observe_acl_state                    # T2 precondition: applied != pre
8.  proof = independent_read_only_proof(grant_set) # {read_only_proof, reobserved_digest, verifier_capture_digest}
8a. reobserved = proof["reobserved_digest"]
    T2 runtime gate: reobserved must == applied     -> else _compensate_and_confirm -> fail closed

        -> else _compensate_and_confirm -> PENDING "...not PLATFORM_ATTESTED..." (attestation NOT requested)

                operator_authorization=operator_authorization, applied_grant_set_digest=applied)

    postcheck = build_pg_observer_bootstrap_postcheck(..., reobserved_post_rollback_digest=reobserved,

9e. return build_pg_observer_bootstrap_applied_result(..., pre_state_digest=pre,
```

Keeping the `evidence_class` first-filter **before** requesting the attestation preserves the exact
existing behaviour for the current `_SimulationProductionDriver` (which reports a non-attested class
and has no `signed_apply_attestation` method): it still fails at 9a with `"...not PLATFORM_ATTESTED..."`,
never reaching 9b. `APPLIED` is emitted **only** when 9a passes and `validate_apply_attestation`
returns `[]`.

The `build_pg_observer_bootstrap_applied_result` signature gains `apply_attestation: dict` and
`apply_attestation_signature: bytes`. Build-time fail-closed guards: `apply_attestation` is a dict;
`evidence_class == PLATFORM_ATTESTED`; `applied != pre`; `attestation.reobserved_digest ==
attestation.applied_grant_set_digest == applied`; strict-base64 body guard on the attestation SSHSIG
(§4). `started_at`/`completed_at`/`evidence_expires_at` are derived from `trusted_host_time`, so the
receipt's own TTL bookkeeping is trusted-anchored, not caller-anchored.

## 2. T3 — compensate-failure must never be a misleading "compensated" PENDING

### 2.1 Confirmed vs unconfirmed compensation

New helper `_compensate_and_confirm(driver, *, grant_set, role) -> bool`:

```
try:
    driver.compensate(grant_set=grant_set)
except Exception:
    return False                       # compensation raised -> NOT confirmed
try:
    return not driver.observer_role_present(role=role)   # re-observe absence -> CONFIRMED iff absent
except Exception:
    return False                       # re-observe failed -> NOT confirmed (fail-closed)
```

Replace both current best-effort `try: driver.compensate(...) except: pass` sites (the 9a non-attested
branch and the outer `except` handler) with this helper:

- **confirmed True** ⇒ the observer is provably gone ⇒ keep the honest `EXTERNAL_VERIFICATION_PENDING`
  with the existing "compensated" reason (backward-compatible: the `_ProofRaisesDriver` test whose
  `compensate` sets `_present=False` still yields `PENDING` "compensated");
- **confirmed False** ⇒ the role may persist in production ⇒ return the new
  **`RECOVERY_REQUIRED`** status with `recovery_required=true` and an explicit residual reason
  (never a "compensated" PENDING).

### 2.2 Additive result status + field

- `RESULT_STATUSES` (module) and the result-schema `status` enum gain **`RECOVERY_REQUIRED`**.
- Additive top-level result field **`recovery_required` (boolean)**, defaulted `false` in
  `_base_result` (so every existing builder inherits `false`), set `true` only on the
  `RECOVERY_REQUIRED` path.
- New builder `build_recovery_required_result(intent, *, reason, now, apply_actor_node,
  ttl_seconds=EVIDENCE_TTL_SECONDS)` — identical shape to `build_pending_result` but
  `status="RECOVERY_REQUIRED"`, `recovery_required=true`, `evidence_class="STRUCTURAL_ONLY"`,
  `apply_attestation=None`, `apply_attestation_signature_pem=None`, `independent_postcheck=None`,
  `rollback_record=None`, `boundary.production_apply_performed=false`, and a `failure_reason` that
  names the stranded role and the manual-recovery requirement. It blocks S2.5 (it is a failure, not a
  success, and the closure predicate admits only `APPLIED_ROLLED_BACK_EXACT`).

Reason strings:

- confirmed compensation (unchanged intent): `"production observer apply driver evidence is not
  PLATFORM_ATTESTED (...); production_apply_performed stays false"` and
  `"production observer apply interrupted and compensated: <exc>"`.
- unconfirmed compensation (new): `"production observer apply RECOVERY_REQUIRED: compensation was NOT
  confirmed (driver.compensate raised or the observer role still present); the observer role may
  persist in production and requires explicit operator recovery; production_apply_performed stays
  false"`.

**Decision — new `RECOVERY_REQUIRED` vs reuse `NOT_RESTORED_FAILED`.** `NOT_RESTORED_FAILED` already
exists but carries disposable semantics (a real `rollback_record` + real operator signature from the
structured-rollback path). The production compensate-failure has no `rollback_record` and a distinct
recovery meaning. A clean additive `RECOVERY_REQUIRED` avoids overloading one status with two shapes
and matches the sibling S2.4 vocabulary (§10.2 lists `RECOVERY_REQUIRED`). See fork F2.

## 3. T4 — required production dependency relation enforced before the driver

Design §2.2 (`docs/execution_plan/ai_ml_landing/design/S2.4-install-source-seams.md:161-169`): *"The
S2.0 effect intent must include read-only access to `learning.alr_consumer_events` so S2.1 can
observe consumer-session state."* The module models a schema-qualified grant as `observed_schema`
(pg_ident) + `observed_relations[]` (pg_idents, no dots), so the exact requirement for a
**production** intent is `observed_schema == "learning"` and `"alr_consumer_events" in
observed_relations`.

New constants:

```
REQUIRED_PRODUCTION_OBSERVED_SCHEMA   = "learning"
REQUIRED_PRODUCTION_OBSERVED_RELATION = "alr_consumer_events"
```

New pre-driver check in `_apply_production_observer_bootstrap`, as **step 2.5** (immediately after the
attested-host guard at step 2, before the SSHSIG check at step 3 and long before any driver call —
so it fires with zero mutation regardless of driver availability and is auth-independent):

```
observed_schema = intent.get("observed_schema")
relations       = intent.get("observed_relations") or []
if observed_schema != REQUIRED_PRODUCTION_OBSERVED_SCHEMA \
   or REQUIRED_PRODUCTION_OBSERVED_RELATION not in relations:
    return build_pending_result(
        intent,
        reason=("production observer intent OMITS the required read-only dependency "
                "learning.alr_consumer_events (design S2.4 §2.2); refusing to invoke the driver"),
        now=now, apply_actor_node=apply_actor_node)
```

This is a policy reject of a structurally-valid intent, so a typed `EXTERNAL_VERIFICATION_PENDING`
(zero mutation) is consistent with the other pre-driver gates (host, SSHSIG, `driver is None`); it is
not a malformed-intent `raise`. It is gated to the production function only, so `disposable_local`
logic proofs (which observe arbitrary throwaway-cluster relations) are unaffected.

## 4. Secret-non-serialization for the new public signature field

`apply_attestation_signature_pem` is another **public** SSHSIG whose armor body can false-positive on
the secret regex; it must be handled exactly like `operator_signature_pem`:

- `_result_secret_scan_view` excludes **both** `operator_signature_pem` and

- The strict-base64 armor-body guard (`_operator_signature_pem_body_is_strict_base64` /

  every builder that sets it, and as an **unconditional** check in

  the new field.

`apply_attestation` itself is a digest/identity/timestamp object with no secret-bearing fields; it is
scanned normally by `_guard_no_secret`.

## 6. Offline result validation and the closure/EFFECT boundary

`validate_pg_observer_bootstrap_result` `APPLIED` branch adds:

- `postcheck.reobserved_post_rollback_digest == result.applied_grant_set_digest` (T2 offline mirror;
  the disposable branch's analogue is `reobserved == pre_state_digest`);
- a new `_apply_attestation_binding_errors(result.get("apply_attestation"),
  result.get("apply_attestation_signature_pem"), intent_id=..., intent_digest=..., source_head=...,
  applied_grant_set_digest=..., operator_authorization=...)` that **structurally** re-binds the
  attestation: exact `ATTESTATION_FIELDS` contract; const identity/fingerprint/algorithm/namespace/
  schema_version/evidence_class; `attestation_digest` integrity; `intent_id/intent_digest/source_head`
  bound to the receipt; `reobserved_digest == applied_grant_set_digest == result.applied_grant_set_digest`
  (T2); and `trusted_host_time` within the **embedded** `operator_authorization` window
  `[issued_at, expires_at)` plus `attestation_expires_at` bounded by `MAX_APPLY_ATTESTATION_TTL` (T5,
  offline). Because `build_operator_authorization` clamps `expires = min(intent_expiry, issued+15m)`
  and `issued == intent.created_at`, the operator-authorization window is a subset of the intent
  window, so the offline T5 check is sufficient without carrying intent times into the result.

This structural binding is the **recommended** offline posture (fork F1), mirroring the existing
honest-boundary treatment of `operator_authorization_binding_errors` (structural-only offline; no
subprocess crypto in the central validator). It is strictly stronger than status quo, which unlocked
`APPLIED` from a bare attribute with no signed evidence at all.

**Genuinely EFFECT-only, out of W0a scope:**

- **OPS-2 closure predicate admitting a production `APPLIED`.** `validate_pg_observer_bootstrap_binding`
  admits only `APPLIED_ROLLED_BACK_EXACT` (the disposable logic proof) and injects no `route_task`
  effect node. Admitting a production `APPLIED` into a closure PASS — binding the **out-of-band
  trusted-host verification that the runtime apply actually happened** — is deferred to the S2.0
  EFFECT session. W0a leaves that predicate untouched. Reason: a packet-local receipt cannot
  authenticate its own execution (Typed Authority Matrix); only an out-of-band trusted-host capability
  can, and that is EFFECT work, not source work.
- **Producing a genuine attestation.** The §9.1 private key is on neither Mac nor `trade-core`. Only
  the S2.0 EFFECT session, with the real trusted host, can sign a valid attestation. W0a lands the
  verification + protocol + schema + throwaway-key tests only.
- **The `apply_attestation` crypto re-verification offline** (fork F1 Option B) is deliberately not
  adopted in the recommended design, to keep the central validator subprocess-free and audit-shim
  safe; the crypto gate lives at apply time where the driver and `ssh-keygen` are genuinely present.

## 8. How tests exercise the signed path without impersonation

The existing disposable tests already mint a **throwaway ed25519 keypair** and monkeypatch
`OPERATOR_PUBLIC_KEY`/`OPERATOR_FINGERPRINT` to it (`_install_operator_profile`, `_sign`). The same
pattern extends to the attestation, without ever claiming a real runtime PASS:

- `_install_attestor_profile(tmp_path, monkeypatch)` mints a throwaway keypair and monkeypatches
  `obs.ATTESTOR_PUBLIC_KEY` / `obs.ATTESTOR_FINGERPRINT` to it (the module reads these constants at
  call time). A test `_sign_attestation(private_key, attestation)` writes `canonical_bytes(attestation)`
  and runs `ssh-keygen -Y sign -n arcane-equilibrium-aiml-s2-observer-bootstrap-apply`.
- A test driver adds `signed_apply_attestation(...)` that returns
  `{"attestation": build_apply_attestation(...), "signature": <throwaway SSHSIG>}` and reports
  `evidence_class="PLATFORM_ATTESTED"`. This exercises the **full** verification path (T1 signature +
  trust-root binding, T2 reobserved==applied, T5 trusted-clock windows) and yields a real `APPLIED`
  receipt round-trip through `validate_pg_observer_bootstrap_result` + the central validator — exactly
  as the disposable `APPLIED_ROLLED_BACK_EXACT` tests already do for the operator authorization.

This does **not** impersonate a platform-attested runtime PASS, because:

1. it verifies the *signature-verification code*, not a real attestation — the fixture's key is a
   throwaway, and the module's honest boundary is that a valid SSHSIG proves integrity + trust-root
   binding, never that the runtime apply happened;
2. the receipt's boundary flags stay honest (`production_running_attested=false`,
   `load_verified=false`, nine authorities false);
3. a **genuine** production `APPLIED` still requires the real §9.1 trust-root private key at the S2.0
   EFFECT session (off Mac/`trade-core`); no fixture holds it, and the closure/EFFECT out-of-band
   trusted-host verification (OPS-2) is what admits a real PASS.

New / updated negative tests (each blocks `APPLIED`, all no-impersonation):

- **T1 core:** a driver with `evidence_class="PLATFORM_ATTESTED"` but a bogus/absent attestation
  (wrong namespace, wrong key without monkeypatch, tampered `attestation_digest`) → compensate →
  `PENDING`/`RECOVERY_REQUIRED`, never `APPLIED`. A throwaway-signed attestation with
  `ATTESTOR_PUBLIC_KEY` **not** monkeypatched → crypto verify fails (proves the fixed trust root is
  the real gate).
- **T2:** `reobserved_digest != applied` (in the attestation and/or the runtime gate) → denied.
- **T5:** expired intent + a historical caller `now` inside the original window, with a real
  `trusted_host_time >= intent.expires_at` → denied (the caller cannot loosen freshness).
- **T3:** a driver whose `compensate` raises (or whose post-compensate `observer_role_present` still
  returns `True`) → `RECOVERY_REQUIRED`, `recovery_required=true`, explicit residual reason, no
  "compensated" PENDING.
- **T4:** a production intent omitting `learning.alr_consumer_events` → `EXTERNAL_VERIFICATION_PENDING`,
  driver untouched (`driver.calls == []`), zero mutation.
- **Existing production-intent factory update:** every existing production test intent must set
  `observed_schema="learning"` and include `"alr_consumer_events"` so it passes T4 and continues to
  exercise the SSHSIG/driver gates. The `_SimulationProductionDriver` remains valid: it reports a
  non-attested class and is rejected at step 9a *before* `signed_apply_attestation` is requested, so
  its existing "…not PLATFORM_ATTESTED…" assertions are unchanged.

## 9. Typed Authority Matrix confirmation

Every change verifies **signed evidence + trust-root binding** and never asserts a runtime fact:

- The module verifies the attestation SSHSIG's integrity and its binding to the pinned §9.1 trust root
  and the exact intent/applied digests. This is `claim_evidence` / `implementation_contract` work.
- It does **not** assert the runtime apply actually happened. `production_apply_performed=true` is a
  *receipt claim*; admitting it as a *fact* (OPS-2 closure predicate) requires the out-of-band
  trusted-host EFFECT verification, which is untouched and out of W0a scope.
- The offline validator/CLI performs structure + integrity + trust-root-binding checks and cannot
  authenticate a PASS (CLAUDE Typed Authority Matrix), exactly as documented for the existing
  operator-authorization binding.

The design does not weaken the fail-closed posture at any point: the caller `now` and
`driver.evidence_class` can only ever *tighten*; the signed attestation is the sole `APPLIED` unlock;
any verification gap compensates and returns a typed non-success (`PENDING`/`RECOVERY_REQUIRED`),
never a fake success, never a stranded role reported as "compensated".

## 11. `DESIGN_DECISION_REQUIRED` forks

- **F1 — offline attestation verification depth.**
  - *Option A (RECOMMENDED):* apply-time full crypto gate (§1.3) + offline **structural-only**
    attestation binding (§6). Consistent with the existing `operator_authorization_binding_errors`
    honest-boundary precedent; keeps the central validator / audit shim subprocess-free; strictly
    stronger than status quo.
  - *Option B:* additionally re-run `_verify_ssh_signature` in the offline result validator. Strongest
    forgery resistance, but introduces an `ssh-keygen` subprocess into `validate_aiml_artifact` (perf +
    sandbox/audit-shim implications) and requires the throwaway-key monkeypatch to stay active during
    central validation in tests. Recommend A; escalate to E3 if maximal offline forgery resistance is
    required.

- **F2 — T3 status name.** New `RECOVERY_REQUIRED` (RECOMMENDED; matches S2.4 §10.2 vocabulary, clean
  additive shape) vs reuse of the existing `NOT_RESTORED_FAILED` (avoids one enum value but overloads a
  disposable-shaped status with a production compensate-failure meaning). Recommend `RECOVERY_REQUIRED`.

- **F3 — attestation identity/namespace.** Distinct attestor identity/namespace on the shared §9.1 key
  (RECOMMENDED; domain-separates post-apply evidence from the pre-approval authorization) vs reusing
  the operator identity/namespace (fewer constants, but lets a pre-approval SSHSIG be replayed as an
  attestation). Recommend distinct.

- **F4 (minor) — T4 strictness.** Require `observed_schema == "learning"` **and** the relation
  (RECOMMENDED; the design names the fully-qualified `learning.alr_consumer_events`) vs accepting the
  relation name under any schema. Recommend the strict schema+relation form.

- **Noted non-P1 semantic wrinkle (no change in W0a):** for a production `APPLIED`, the reused
  `pg_observer_bootstrap_postcheck` hardcodes `restoration_confirmed=true` even though the observer is
  intentionally left provisioned (no rollback). This is outside the 5 P1s and the postcheck builder is
  shared with the disposable path; changing it risks scope creep and does not affect the fail-closed
  posture. Flag for a later focused pass if the field's production semantics need tightening.
