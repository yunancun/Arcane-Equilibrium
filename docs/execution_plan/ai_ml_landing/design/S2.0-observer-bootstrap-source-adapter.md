## §1 What is real vs deferred (honest split, CLAUDE Typed Authority Matrix)

- **REAL / `LOCAL_REPRODUCIBLE` on this Mac** (disposable-cluster tests): a real `postgres` process emits a
  genuine `42501` (observer write + SET ROLE escalation denied) and `28P01` (credential escalation denied);
  a real `CREATE ROLE … NOLOGIN NOSUPERUSER …` + `GRANT USAGE`/`GRANT SELECT` apply and `REVOKE`/`DROP ROLE`
  rollback with a real `pre == post` catalog-projection digest; a real operator SSHSIG verified by
  `/usr/bin/ssh-keygen -Y verify` (throwaway test key + monkeypatch).
- **Honestly DEFERRED** to the S2.0 EFFECT session (recorded as such, never simulated): the real production PG
  socket, the real production observer role, a platform-attested runtime PASS, and the out-of-band operator
  SSHSIG over the exact production intent. A `LOCAL_REPRODUCIBLE` label / a self-hashed receipt authenticates
  integrity only — never who executed what or that an external fact is true. Any consumer relying on this must
  re-run the disposable proof or obtain platform attestation.

## §2 The exact minimal read-only observer (structured allowlist, never raw SQL)

`generate_observer_grant_sql(intent)` is the single SSOT. The intent carries a **`grant_set_selector` enum**
(`observer_read_only_v1`, the only admissible value) plus the observed schema + relation list — never SQL. It
emits exactly:

```
CREATE ROLE <obs> NOLOGIN NOSUPERUSER NOCREATEROLE NOCREATEDB NOREPLICATION NOBYPASSRLS
GRANT USAGE ON SCHEMA <observed> TO <obs>
GRANT SELECT ON <observed>.<relation> TO <obs>   -- for each observed relation
```

with the connection pinned `default_transaction_read_only=on search_path=pg_catalog` and peer/ident local
auth (no password ingress). All `FORBIDDEN_ROLE_ATTRIBUTES` are explicitly absent. Identifiers pass the S1.5
`_pg_ident` allowlist (`^[a-z_][a-z0-9_]*$`); a role/schema/relation naming a privileged identity is refused.
It **raises (fail-closed)** on: a broader selector, a raw-SQL / injection identifier, a privileged role name,
a non-peer/ident auth, or any over-grant marker key (`privileges`, `with_grant_option`, `role_membership`,
`raw_sql`, `writer`, `superuser`, `migration`, …). Rollback is exact `REVOKE ALL` + `DROP ROLE IF EXISTS`.

## §3 Operator SSHSIG gate (domain separation)

`apply_observer_bootstrap` requires a VALID operator SSHSIG over the exact intent + source head. It reuses the
S0.3/S1 trust-root **public key/fingerprint** but a **distinct identity + namespace** so an S1 target-host
permit cannot be replayed as an S2 observer authorization:

- identity `aiml-s2-observer-bootstrap-operator-v1`
- namespace `arcane-equilibrium-aiml-s2-observer-bootstrap`

The private key is on neither Mac nor trade-core. Authorization is **intent-derived**, never a user env flag.
Without a valid SSHSIG → typed `EXTERNAL_VERIFICATION_PENDING`. A **production** target ALSO returns
`EXTERNAL_VERIFICATION_PENDING` in this WP2 source lane (the real socket / apply is the S2.0 EFFECT session);
only a `disposable_local` target with a valid SSHSIG and an injected throwaway-cluster connection runs the real
structured SQL. **Applier ≠ independent verifier**: the applier does apply→rollback; a distinct verifier
(distinct role/node/process/capture) re-derives the observer and observes the read-only denials, and the result
embeds that verifier's postcheck.

## §4 Four typed artifacts (`program_code/ml_training/schemas/aiml_gate_receipts/`)

1. `pg_observer_bootstrap_intent_v1` — target host/endpoint/database/observer role, peer/ident auth mapping,
   the enum `grant_set_selector`, observed schema + relations, TTL, applier + distinct postcheck node,
   `target_class` (disposable_local | production), 40-hex source head.
2. `pg_observer_bootstrap_result_v1` — pre-state catalog digest, applied grant-set digest, embedded
   independent postcheck, embedded rollback record, embedded non-secret operator authorization + public SSHSIG
   bytes, a `status` incl. `EXTERNAL_VERIFICATION_PENDING`, and the const-false boundary
   (`production_apply_performed:false` / `production_running_attested:false` / `load_verified:false` /
   `nine_authorities_false:true`, mirroring `agent_governance_sealed_build.py`).
3. `pg_observer_bootstrap_postcheck_v1` — the independent-verifier attestation embedding the observer's own
   read-only proof: write → `42501`, SET ROLE escalation denied, search_path reset harmless (queries
   pg_catalog-qualified), credential escalation → `28P01`; bound to the verifier's own governed
   `command_capture_v2` record digest.
4. `pg_observer_bootstrap_rollback_v1` — the exact `REVOKE`/`DROP` record with a `pre == post` catalog
   projection (the observer is gone).
