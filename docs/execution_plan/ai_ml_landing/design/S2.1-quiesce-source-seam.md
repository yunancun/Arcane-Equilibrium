## §1 The subject: who exactly is the ALR runtime owner

The "ALR runtime" is the long-lived learning-runtime consumer, established as a single concrete owner by two
committed source facts:

- **Unit** — `helper_scripts/deploy/openclaw-alr-shadow.service.template` — a **user-level** systemd service
  `openclaw-alr-shadow.service`, `Type=exec`, `WantedBy=default.target`, with:
  - `ExecStart=/usr/bin/python3 -m ml_training.alr_event_consumer --dsn-file %h/.config/openclaw/alr-shadow.dsn
    --lock-file %t/alr-shadow/consumer.lock --max-batch 32`
  - `WorkingDirectory=%h/BybitOpenClaw/srv`, `Environment=PYTHONPATH=…/program_code`,
    `Environment=ALR_SOURCE_HEAD=__ALR_SOURCE_HEAD__` (installer stamps the immutable deployed commit),
    `ALR_CANDIDATE_EVIDENCE_DIR`, `ALR_CANDIDATE_POLICY_FILE` (S2.4 also sets
    `ALR_EXPECTED_LEARNING_RUNTIME_DIGEST_V2`).
  - restart policy `Restart=on-failure`, `RestartSec=5`, `TimeoutStopSec=30`; cgroup caps `MemoryMax=512M`,
    `TasksMax=64`; hardening `NoNewPrivileges=true`, `PrivateTmp=true`, `ProtectSystem=full`,
    `RestrictAddressFamilies=AF_UNIX AF_INET`, `UMask=0077`; `RuntimeDirectory=alr-shadow` (mode 0700).
  - **No `WatchdogSec`.** Liveness today is the `Restart=on-failure` machinery, not an sd_notify watchdog. The
    real watchdog reset drill is S2.5 (`WATCHDOG_ROLLBACK_TEST`); S2.1 only *observes* watchdog-last.
- **Process** — `program_code/ml_training/alr_event_consumer.py`:
  - entrypoint `main()` → `run_event_consumer(dsn_path, lock_path, …)`.
  - **two single-instance locks**: (a) a **PG session advisory lock**
    `acquire_single_instance` → `pg_try_advisory_lock(hashtext('alr_event_consumer_v1'))`
    (`_SINGLE_INSTANCE_LOCK_NAME = "alr_event_consumer_v1"`); (b) a **flock**
    `runtime_file_lock(lock_path)` → `fcntl.flock(fd, LOCK_EX | LOCK_NB)` on `%t/alr-shadow/consumer.lock`.
  - **graceful stop**: `_install_shutdown_handlers` traps `SIGTERM`/`SIGINT` → sets `stop_event` → the loop
    drains, then `stop_consumer_session`, `release_single_instance`, `connection.close()`. A clean
    `systemctl stop` (SIGTERM within `TimeoutStopSec=30`) therefore drains and releases both locks — this is
    the reversible quiesce primitive.
  - **DSN identity** (`_LOCAL_DSN_REQUIRED`): `host=127.0.0.1 port=5432 dbname=trading_ai user=alr_shadow`
    (least-privilege shadow role); `_DSN_FORBIDDEN_KEYS` blocks `hostaddr/service/servicefile`.
  - **queue**: PG `LISTEN alr_scanner_snapshot_v1` (`ALR_SCANNER_NOTIFY_CHANNEL`) + a Linux inotify watch on
    the candidate-evidence dir.
  - **runtime-digest binding**: `resolve_pinned_learning_runtime_digest()` proves the committed v2
    `learning_runtime_digest` recomputes from the checkout (`try_build_learning_runtime_manifest_v2`) before
    any DB — a HEAD-independent identity value-guard (source `learning_runtime_manifest.py`; pin receipt
    `docs/execution_plan/ai_ml_landing/receipts/S2.2A-source-compatibility-receipt-v2.json`).
- **Consumer session ledger** — `program_code/ml_training/alr_consumer_repository.py`: `start_consumer_session`
  / `stop_consumer_session` / `fail_consumer_session` / `find_unclosed_session` append immutable rows to
  `learning.alr_consumer_events` with `event_kind ∈ {SESSION_STARTED, SESSION_STOPPED, SESSION_FAILED,
  UNCLEAN_RECOVERY, NOTIFICATION_RECEIVED, …}`. An **open** session = a `SESSION_STARTED` with no terminal
  event (`find_unclosed_session` returns it); a **quiesced** session = a terminal `SESSION_STOPPED` exists and
  no unclosed session remains.
- **S1.6 identity** — the final runtime choice is `content_addressed_fixed_path` (fixed-path
  `/usr/bin/python3 -m …`, NOT OCI). So the owner is a **fixed-path Python invocation under a named user unit**,
  not a container — the ownership predicate binds to the unit + PID + cgroup + fixed-path cmdline + source
  head, exactly the facts S1.6 selected.

**Why this matters for the mandate.** All the signals the operator requires (owner / process / unit / cgroup /
env-hash / restart-policy / watchdog / queue / credential-exposure) are already concrete, single, and
machine-observable for this one unit. The S2.1 seam does not invent an owner model; it *confirms this exact
one* and refuses to act on anything ambiguous.

## §2 What is real vs deferred (honest split, CLAUDE Typed Authority Matrix)

- **REAL / `LOCAL_REPRODUCIBLE` on this Mac** (disposable lane): (a) via the **S2.0 observer role** on a real
  throwaway PG cluster — a real `pg_try_advisory_lock('alr_event_consumer_v1')` acquired by one throwaway
  backend and observed **held**, then **released**, through a genuine read-only `pg_locks` /
  `pg_stat_activity` / `learning.alr_consumer_events` read AS the observer; (b) the ownership-confirmation
  predicate, static-guard sampling, and owner-scoped fence/un-fence LOGIC exercised against a
  **simulated-owner harness** (a temp `/proc/<pid>` tree + an injected `systemctl show` command runner); (c) a
  real operator SSHSIG verified by `/usr/bin/ssh-keygen -Y verify` (throwaway key + monkeypatch).
- **Honestly DEFERRED** to the S2.1 EFFECT session (recorded, never simulated as PASS): reading the **live**
  ALR `/proc` + `systemctl show`, the **live** `systemctl --user stop/start openclaw-alr-shadow.service`, the
  **live** production PG observer reads, a platform-attested runtime PASS, and the out-of-band operator SSHSIG
  over the exact production intent. A `LOCAL_REPRODUCIBLE` label / self-hashed receipt authenticates integrity
  only — never who executed what or that a live process was quiesced.

This is the exact S2.0 split: S2.0's production PG apply is fail-closed and only a `disposable_local` throwaway
cluster runs real SQL; S2.1's production **fence** is fail-closed and only a `disposable_local` **simulated
owner** runs the real (simulated) fence/observe/un-fence.

## §3 Ownership-confirmation predicate (mandate #1 — the safety crux)

`confirm_alr_owner(inventory, *, expected_fingerprint)` returns a `quiesce_observation_v1` (phase
`PRE_FENCE_INVENTORY`) with exactly one verdict. It **fences only** on `CONFIRMED_SINGLE_OWNER`.

**Confirming signals — ALL must agree on ONE owner** (a mismatch in any one → not confirmed):

| # | Signal | Source (SOURCE lane = simulated; EFFECT lane = live) | Confirms |
|---|---|---|---|
| 1 | unit | `systemctl --user show openclaw-alr-shadow.service -p LoadState,ActiveState,SubState,MainPID,ExecMainStartTimestampMonotonic,NRestarts,InvocationID,FragmentPath,DropInPaths,ControlGroup,Environment,NeedDaemonReload` → `loaded/active/running`, `FragmentPath==<unit path>`, `DropInPaths==""`, `NeedDaemonReload==no` | the exact **long-lived unit**, no drop-in override, no pending reload |
| 2 | process (PID) | `MainPID=P>0`; `/proc/P/stat` field 20 `starttime` + `/proc/sys/kernel/random/boot_id` | the exact process **instance** (start-ticks + boot-id pin it across the window) |
| 3 | invocation | `/proc/P/cmdline` == `python3 -m ml_training.alr_event_consumer --dsn-file … --lock-file … --max-batch 32`; `InvocationID` present | it is the ALR **long-lived** invocation, **not a head-specific / rollforward / probe wrapper** |
| 4 | cgroup | `ControlGroup` / `/proc/P/cgroup` == the unit's `…/openclaw-alr-shadow.service` cgroup | P ∈ the unit's cgroup (not a stray cmdline match outside the unit) |
| 5 | env-hash | sha256 over `/proc/P/environ` restricted to the unit's declared keys (`ALR_SOURCE_HEAD`, `PYTHONPATH`, `ALR_CANDIDATE_*`) == the unit's declared Environment set | the process runs the **deployed** env + source head |
| 6 | runtime-digest | `ALR_SOURCE_HEAD` (from #5) → the committed v2 `learning_runtime_digest` recomputes (`resolve_pinned_learning_runtime_digest`) | the owner is bound to the exact **learning-code identity** (S1.6 / S2.2A / WP1) |
| 7 | DB single-instance | via **S2.0 observer role** (read-only): `pg_locks` shows `objid == hashtext('alr_event_consumer_v1')` **held by exactly one** backend; that backend in `pg_stat_activity` matches the ALR connection; `find_unclosed_session`-style query shows **one** open `SESSION_STARTED` | PG guarantees at-most-one advisory-lock holder → authoritative single-owner |
| 8 | flock | the process holds `flock` on `%t/alr-shadow/consumer.lock` (observed via `/proc/P/fdinfo` or `lslocks`-class read; EFFECT lane) | the local single-instance lock is held by P |

**Verdicts:**
- `CONFIRMED_SINGLE_OWNER` — every signal agrees and `candidate_count == 1`. Only then may the fence proceed.
- `STALE_OWNER` — the intent's `expected_fingerprint` names an owner that is **gone**: `/proc/P` absent, or
  unit `inactive`, or the advisory lock is **free**, or the recorded MainPID no longer matches. **Fail-closed;
  do NOT fence** (there is nothing to fence, and fencing an absent owner could mask a different live owner).
- `AMBIGUOUS_MULTIPLE_OWNERS` — `candidate_count ≥ 2`: two processes carry the ALR cmdline, OR the
  advisory-lock holder PID ≠ the unit MainPID, OR a systemd `scope` (not the `service`) also matches. **Refuse;
  do NOT guess.**

`expected_fingerprint` (in the intent) is the composite `owner_fingerprint` =
`canonical_digest({unit, main_pid, process_start_ticks, boot_id, control_group, env_hash, invocation_id,
cmdline_digest, runtime_digest, advisory_lock_objid, flock_path})`. The whole quiesce cycle binds to this one
digest; pre-fence, in-window, and post-un-fence observations all recompute it and compare.

## §4 Owner-scoped, reversible fence (mandate #2)

The fence is **NOT** `pkill -f alr_event_consumer`, **NOT** `kill <pid>` chosen by name, **NOT** a broad
pattern sweep. It is the confirmed unit's **own lifecycle stop**, gated on §3:

- **Fence** = `systemctl --user stop openclaw-alr-shadow.service` targeting the exact `CONFIRMED_SINGLE_OWNER`
  unit. This delivers SIGTERM inside the unit's cgroup only (owner-scoped, zero collateral), the consumer's
  `_install_shutdown_handlers` drains gracefully within `TimeoutStopSec=30`, both locks release, and the unit
  settles `inactive/dead`. Because a clean `stop` is not a *failure*, `Restart=on-failure` does **not** fight
  it.
- **Un-fence / rollback** = `systemctl --user start openclaw-alr-shadow.service`; the restoration crux is
  `pre_fence_owner_fingerprint` vs `post_unfence_owner_fingerprint` — restored means the owner is back and
  **healthy** (a new PID/InvocationID is expected; what must match is the *stable identity*: unit + cmdline +
  cgroup + env-hash + runtime-digest + advisory-lock re-held by exactly one). Structured record
  `quiesce_rollback_v1`.
- The cycle is **bounded** by the observation window (§5) and a TTL; every path attempts un-fence, even on
  failure, so the runtime is never left fenced by this seam.

**Guard against the "head-specific wrapper" substitution (mandate #2).** Signal #3 + #4 + #7 jointly refuse any
transient wrapper: a rollforward/probe process (e.g., matching the `p0b_alr_*` or `target_host_*` wrappers) is
not the unit MainPID, is not in the service cgroup, and does not hold `alr_event_consumer_v1`. If such a
candidate appears alongside the real owner → `AMBIGUOUS_MULTIPLE_OWNERS` (refuse); if it appears *instead of*
the real owner → not `CONFIRMED` (its cmdline ≠ the long-lived invocation) → fail-closed.

**SOURCE lane realization.** The applier calls an **injected** `fence_ops` object (default `None`). With
`target_class=production` or `fence_ops is None` the applier returns `EXTERNAL_VERIFICATION_PENDING` (no host
contact) — identical to how S2.0 defers when `disposable is None`. With `target_class=disposable_local` + a
valid SSHSIG + an injected simulated-owner `fence_ops`, the "stop" flips the injected `systemctl` state to
`inactive` and releases the throwaway advisory lock; the "start" restores them. No real process is ever
signalled.

## §5 Bounded observation-window static guards (mandate #4)

`quiesce_intent_v1.observation_window = {duration_seconds, min_samples, sample_interval_seconds}` with
`duration_seconds ∈ [MIN_WINDOW_SECONDS, TTL_CEILING_SECONDS]` and `min_samples ≥ 2`. After the fence, the
verifier collects `≥ min_samples` `quiesce_observation_v1` samples (phase `IN_WINDOW_STATIC_GUARD`) spanning
`≥ duration_seconds` at the declared cadence, using an **injected monotonic clock** (deterministic tests, same
pattern as the p0b observer's `monotonic_seconds` injection). Each sample must show
`STATIC_GUARDS_HELD`, defined as ALL of:

- **no restart** — `NRestarts` unchanged since fence AND no new `InvocationID` AND `ActiveState` stays
  `inactive` (`SubState=dead`), i.e. the unit did not auto-restart.
- **watchdog-last** — the last lifecycle transition is the fence itself; no supervening restart (watchdog- or
  `Restart=`-driven) occurred after it. (`WatchdogUSec` is recorded as `none` today; if S2.5 later adds a
  watchdog, a watchdog-triggered restart would flip `ActiveState` and this guard would catch it.)
- **queue-drained** — via the **S2.0 observer role** (read-only): the `alr_event_consumer_v1` advisory lock is
  **free**, no ALR backend remains in `pg_stat_activity`, the consumer session shows a terminal
  `SESSION_STOPPED` (no dangling `SESSION_STARTED`), and the `alr_scanner_snapshot_v1` LISTEN backlog is not
  growing under an (absent) consumer.

Window failure modes → `OBSERVATION_WINDOW_VIOLATED` (fail-closed, un-fence still attempted): fewer than
`min_samples`; span `< duration_seconds`; any sample `RESTART_DETECTED` (a restart supervened) or
`QUEUE_NOT_DRAINED`.

## §6 Reuse of the S2.0 read-only observer (mandate #3)

The DB-side evidence is collected **only** through the S2.0 observer role — no new privileged DB path:

- `agent_governance_alr_quiesce_fence.py` imports `agent_governance_pg_observer_bootstrap` and, in the disposable
  lane, **chains** S2.0 → S2.1: it builds the observer grant-set (`generate_observer_grant_sql`), applies it on
  the throwaway cluster (`observer_bootstrap_apply`), then connects **AS the observer** (read-only,
  `default_transaction_read_only=on`, `search_path=pg_catalog`) to read `pg_locks` / `pg_stat_activity` /
  `learning.alr_consumer_events`. This is a real end-to-end proof that the quiesce evidence is observable under
  least privilege.
- **Integration requirement for the EFFECT session (flag to PM/OPS):** the S2.0 observer intent's
  `observed_relations` must include the ALR consumer-session relation (`learning.alr_consumer_events`) so the
  observer can `SELECT` it. `pg_locks` / `pg_stat_activity` are `pg_catalog` system views already reachable
  under the observer's pinned `search_path=pg_catalog` and need no extra grant. The queue/lock evidence is thus
  fully within the S2.0 observer's read-only envelope.
- The **host-side** read-only reader (systemd/proc) reuses the **discipline** proven by
  `p0b_alr_current_head_two_cycle_observer_v2.py:build_readonly_runtime_module` — an **allowlisted**
  `systemctl --user show -p <fixed property set>` + `/proc/P/{stat,cmdline,environ,cgroup}` reader that raises
  on any non-allowlisted command. S2.1 **re-implements** this narrow allowlist locally (the p0b module is
  hard-coupled to fixed paths / uid 1000 / a target-head drift-fail and must not be imported), citing it as
  prior art. In the SOURCE lane the reader runs against the injected/simulated harness; the live reader is
  DEFERRED to EFFECT.

## §8 Result status vocabulary (fail-closed by construction)

| status | when | evidence_class | boundary |
|---|---|---|---|
| `QUIESCED_STATIC_GUARDS_HELD` | disposable happy path: confirmed → fenced → all window samples held → un-fenced/restored | `LOCAL_REPRODUCIBLE` | live_alr_owner_fenced=false |
| `EXTERNAL_VERIFICATION_PENDING` | no valid SSHSIG, OR `target_class=production`, OR `fence_ops is None`, OR intent outside its validity window | `STRUCTURAL_ONLY` | all false |
| `STALE_OWNER_FAIL_CLOSED` | §3 verdict `STALE_OWNER` (expected owner gone) — no fence attempted | `STRUCTURAL_ONLY` | all false |
| `AMBIGUOUS_OWNER_REFUSED` | §3 verdict `AMBIGUOUS_MULTIPLE_OWNERS` — refuse, no fence | `STRUCTURAL_ONLY` | all false |
| `OBSERVATION_WINDOW_VIOLATED` | §5 window failure (restart supervened / too few samples / queue not drained) — un-fence attempted | `STRUCTURAL_ONLY` | all false |
| `NOT_RESTORED` | fence applied but un-fence failed (owner not back healthy) — honest failure | `STRUCTURAL_ONLY` | all false |
| `FAILED` | any other fail-closed condition | `STRUCTURAL_ONLY` | all false |

Production fence NEVER succeeds in this WP3 source lane, and no path returns success without the full
confirmed→fenced→held→restored cycle on a disposable simulated owner.

## §9 Operator SSHSIG gate (domain separation)

`apply_quiesce_fence` requires a VALID operator SSHSIG over the exact intent + source head. It reuses the
S0.3/S1 trust-root **public key/fingerprint/algorithm** from `agent_governance_aiml_trusted_host`
(`S1_TRUSTED_TARGET_HOST_PUBLIC_KEY`, `EXPECTED_S1_TARGET_HOST_SIGNER_FINGERPRINT`,
