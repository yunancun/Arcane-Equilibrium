## 0. Why this amendment, in one paragraph

The merged WP3 seam is structurally correct (confirmed-single-owner predicate → owner-scoped reversible
fence → bounded static-guard window → un-fence, all fail-closed, all simulated), but it is bound to the
**wrong owner identity**: a per-user `systemctl --user` service `openclaw-alr-shadow.service` running
`/usr/bin/python3 … --dsn-file <home path>` as `alr_shadow`. §8 replaces that legacy template with a
system-level unit. Realigning WP3 is therefore an **identity retarget**, not a redesign: the same predicate,
the same fence mechanism, the same four typed artifacts — pointed at the §8 system unit. The change is
minimal-coherent because (a) the fence mechanism is already injected (`fence_ops.stop()/start()`) and
unit-name-agnostic; (b) the DB-side signals are already parameterized; (c) the only structural tightening is
the C1 invocation fingerprint, which must reject `/usr/bin/python3` (system Python) and accept the §8
content-addressed interpreter plus `-I`.

### 1.1 Why `arcane-equilibrium-aiml-engine-scanner.service`

1. **Component-class coherence.** §4 of the S2.4 design classifies the ALR event-consumer install under the
   `ENGINE_SCANNER` component-effect class (adapter `engine_scanner_deploy_adapter_v1`). The unit name
   carries the `engine-scanner` component so a host operator reading `systemctl status` sees one identity
   across unit, `User=`, `RuntimeDirectory`, and `StateDirectory` (all `…aiml-engine-scanner`).
2. **Product namespace, not retired control-plane prefix.** The `openclaw-*` prefix belongs to the retired
   OpenClaw Gateway/control-plane family (removed 2026-07-16). System-level AIML units should namespace under
   the formal product `arcane-equilibrium` to avoid host-wide unit-name collisions and to stop implying a
   dependency on the retired control plane.
3. **Mirrors the §8 directory namespace.** `RuntimeDirectory=arcane-equilibrium/aiml-engine-scanner` and
   `StateDirectory=arcane-equilibrium/aiml-engine-scanner` already fix the `arcane-equilibrium` +
   `aiml-engine-scanner` segments; the unit name uses the same segments joined by hyphens, the standard
   systemd system-unit convention.
4. **`%d` resolves cleanly.** `LoadCredentialEncrypted` places the credential at
   `/run/credentials/<full-unit-name>/pg-dsn`; with this unit name that is
   `/run/credentials/arcane-equilibrium-aiml-engine-scanner.service/pg-dsn`, which is exactly the resolved
   `%d/pg-dsn` the fingerprint must match (see §4).

This is the only genuine naming fork §8 leaves open; §7 lists it for PM confirmation but recommends
proceeding with this value.

> Coordination note (WP4-owned, non-blocking for WP3): §8 writes `WorkingDirectory=/var/lib/arcane-equilibrium/aiml/engine-scanner`
> (slash form) while `StateDirectory=arcane-equilibrium/aiml-engine-scanner` resolves to
> `/var/lib/arcane-equilibrium/aiml-engine-scanner` (hyphen form). WP3 does **not** observe `WorkingDirectory`,
> so this discrepancy does not affect the fence; WP4 must reconcile the two `/var/lib` paths when it renders

## 3. C1 invocation fingerprint — `_is_alr_longlived_cmdline`

This is the only structural (non-constant) change. The merged code already uses `--dsn-file`/`--lock-file`/
`--max-batch` and already matches an absolute interpreter by basename (`args[0].rsplit("/",1)[-1] in
{"python3"}`). Two §8 facts force a change: (a) the interpreter must be the **content-addressed** path under
`/opt/…/runtimes/…/bin/python3` — a bare `/usr/bin/python3` (system Python, the legacy shape §8 rejects)
must now FAIL; (b) `-I` is inserted between the interpreter and `-m`, so the token count is **10, not 9**.

### 3.1 The exact §8 ExecStart, as it appears resolved in `/proc/<pid>/cmdline`

systemd resolves specifiers before exec, so the kernel-stored argv contains **resolved absolute paths**, not
literal `%d`/`%t`. The observed cmdline is exactly ten tokens:

```text
[0] /opt/arcane-equilibrium/aiml/runtimes/<runtime-content-digest>/bin/python3   value-bound (digest segment), fixed shape
[1] -I                                                                            FIXED
[2] -m                                                                            FIXED
[3] ml_training.alr_event_consumer                                               FIXED
[4] --dsn-file                                                                    FIXED (flag name)
[5] /run/credentials/arcane-equilibrium-aiml-engine-scanner.service/pg-dsn        value-bound == expected_dsn_file
[6] --lock-file                                                                   FIXED (flag name)
[7] /run/arcane-equilibrium/aiml-engine-scanner/consumer.lock                     value-bound == expected_lock_file
[8] --max-batch                                                                   FIXED (flag name)
[9] 32                                                                            value-bound bounded int (1..4096)
```

The `%d`/`%t` specifiers **never** appear in `/proc` — the fingerprint matches the resolved paths. Two value
contracts follow (both are intent/probe VALUES, not schema changes):

- `intent["flock_path"]` MUST be the resolved `/run/arcane-equilibrium/aiml-engine-scanner/consumer.lock`,
  never the literal `%t/…`. (`expected_lock_file = intent["flock_path"]`.)
- `host_probe.dsn_stat()["dsn_file_path"]` MUST be the resolved
  `/run/credentials/arcane-equilibrium-aiml-engine-scanner.service/pg-dsn`. (`expected_dsn_file =
  dsn_stat()["dsn_file_path"]`.)

### 3.2 Exact fingerprint rules (retargeted)

Constants:

- `_ALR_CMDLINE_TOKEN_COUNT = 10` (was 9).
- New `_ALR_RUNTIME_INTERPRETER_RE = re.compile(r"^/opt/arcane-equilibrium/aiml/runtimes/[^/]+/bin/python3$")`.
  The `[^/]+` digest segment is intentionally **not** pinned to an exact hex length/encoding: §8 writes the
  segment as `<runtime-content-digest>` without pinning its wire form, and the exact form belongs to the S2.3
  `content_addressed_fixed_path` convention. The regex still enforces the two §8-decisive facts — an absolute
  path under the sealed runtimes root (so `/usr/bin/python3` and any `PYTHONPATH`/home-relative Python fail)
  and basename `python3`. (Optional hardening, not required for §8 alignment: cross-check the segment against
  the `ALR_EXPECTED_LEARNING_RUNTIME_DIGEST` env value; left out to avoid assuming the path/env digest
  encodings are identical — that coupling is not stated by §8.)
- **Anti-traversal guard (as-built; E2/E3/E4 review fix).** `[^/]+` alone matches a `.` or `..` segment, so
  `…/runtimes/../bin/python3` would `fullmatch` yet resolve **outside** the sealed root — contradicting the
  "under the sealed runtimes root" invariant. The implementation therefore adds, right after the regex, a
  `posixpath.normpath(args[0]) == args[0]` equality guard (rejects `.`/`..`/`//`/trailing-slash). The digest
  segment charset is deliberately left permissive (so a `sha256:…`-style wire form is not falsely rejected);
  normalization equality is the wire-form-agnostic gate. Independent of the operator-SSHSIG fingerprint gate,
  which already blocks a false CONFIRMED (E3: the `..`-argv has a different `cmdline_digest`).
- `_ALR_INTERPRETER_BASENAMES` / the loose `startswith` history is replaced by the regex (basename `python3`
  is implied by the regex tail). `_ALR_CONSUMER_MODULE`, `_ALR_APPROVED_FLAGS`, `_ALR_MAX_BATCH_CEILING`
  unchanged.

`_is_alr_longlived_cmdline(args, *, expected_dsn_file, expected_lock_file)` (same signature) becomes:

1. `len(args) == 10` else reject.
2. `_ALR_RUNTIME_INTERPRETER_RE.fullmatch(args[0])` else reject (content-addressed interpreter; rejects
   system Python).
3. `args[1] == "-I"` else reject.
4. `args[2] == "-m"` and `args[3] == _ALR_CONSUMER_MODULE` else reject.
5. `tail = args[4:]` (6 tokens = 3 flag/value pairs); exact `{--dsn-file, --lock-file, --max-batch}`, no
   duplicate, no unknown/extra (unchanged pairing logic, just shifted from `args[3:]` to `args[4:]`).
6. `flags["--dsn-file"] == expected_dsn_file` and `flags["--lock-file"] == expected_lock_file`.
7. `--max-batch` is a bounded positive int `1..4096`.

`_scan_candidate_pids` and the `main_pid_invocation_ok` (C2) call sites are unchanged — they already pass
`expected_dsn_file`/`expected_lock_file` through. The FIX-C2 binding (`candidate_pids == [main_pid]` and
`main_pid_invocation_ok`) and FIX-C3 post-unfence re-check inherit the tightened fingerprint automatically.

**New EFFECT-contract requirement from the system-scope move (OPS MED-1).** A `--user` stop/start ran under the
invoking user's own systemd manager (no escalation); a **system-level** `systemctl stop/start
arcane-equilibrium-aiml-engine-scanner.service` requires **system-manager privilege** — root, or a polkit rule
granting `org.freedesktop.systemd1.manage-units` for this unit — on the EFFECT applier. The unit's own process

recorded on the S2.1 EFFECT operator-input list: if the applier lacks the privilege, `fence_ops.stop()` fails

privileged stop that succeeds followed by an un-fence `start()` failure → `NOT_RESTORED` with the unit left
down, needing the privileged break-glass `sudo systemctl start` / `reset-failed` on that exact unit.

The `owner_scoped_fence`/`owner_scoped_unfence` bodies themselves need **no code change** (they call the
injected `fence_ops`), and `apply_quiesce_fence` orchestration is unchanged — the production/live branch stays
fail-closed `EXTERNAL_VERIFICATION_PENDING`, sequenced after S2.4 install + S2.5 start per §1.2 of the S2.4
