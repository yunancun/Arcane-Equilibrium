### 2.2 非 scope（硬邊界，測試釘死）

- **零 runtime 接觸**：不 `enable`/`start`/`stop`/`restart`/`reset-failed`/`daemon-reload` 任何真實 unit，
  不 signal 任何進程，不讀 live `/proc` 或 live `systemctl`（fixtures 全部走注入 harness）。
- **零 PG 接觸**：不連 production PG；disposable-PG lane 只在 throwaway cluster 上以 S2.0 observer role
  讀 `pg_locks`/`pg_stat_activity`/`learning.alr_consumer_events`（S2.1 §6 同款）。
- **零 systemd 實體**：不寫 `/etc/systemd/system`、不建 transient unit（S2.5 連 S2.4 那種 signed
  transient probe 都沒有——它的 effect 對象是已安裝 unit 本身）。
- **fixture 不得假冒 platform-attested PASS**：任何 fixture/simulated 產物的 `evidence_class` 至多
  `LOCAL_REPRODUCIBLE`；`RUNNING_ATTESTED`/`FINAL_ATTESTED` 兩個成功 status 只能由驗簽通過的
  trusted-host attestor 簽章解鎖（§5.6）。CLAUDE.md 硬邊界 + A2 原文雙重要求。
- **不修 S2.3/S2.4 receipts**：`expected_identity_receipt_v1.running_attested.*==false` 等是 S2.3 的
  歷史事實，S2.5 以**新的 immutable artifact** 疊加證據，永不回寫（S2.4 §3 同款規則）。
- 不動 frozen S0.3 classifier、不動 `PROGRAM_SCHEMA_PATHS`、不動 v1/v2 component-effect matrix bytes。
- 無 broker/order/Decision-Lease/Cost-Gate/Demo/mainnet 接觸。

## §3 被證主體：S2.5 到底 attest 什麼

**Subject** 是 S2.4 §8 安裝的那一個 system unit：`arcane-equilibrium-aiml-engine-scanner.service`
（`User=aiml-engine-scanner`，ExecStart=`/opt/arcane-equilibrium/aiml/launches/<launch_bundle_digest>/bin/python3
-I -B -m ml_training.alr_event_consumer …`，`LoadCredentialEncrypted=pg-dsn`，`Restart=on-failure`、
`RestartSec=30s`、`RestartPreventExitStatus=78`、**無 `WatchdogSec`**）。owner 確認謂詞直接複用 WP3 的
`agent_governance_alr_quiesce_inventory`（UNIT_NAME/C1 指紋/allowlisted show reader），不再發明第二套。

**S2.5A（initial start + running attestation）證明鏈**，每步是 typed 欄位（§5.2）：

1. **precheck（start 前，全部 fail-closed）**：
   a. `S2.4@EFFECT_DONE_INACTIVE` 的 `s2_4_install_effect_receipt_v1(status=APPLIED_INACTIVE)` digest
      在手且未過期；unit 現態 loaded/disabled/inactive、`FragmentPath` 與 fragment digest 等於該 receipt
      所綁 rendered-unit digest、`DropInPaths==""`、`NeedDaemonReload=no`（#36 精神：evidence 綁 exact
      rendered unit，不接受名字相同的替身）；
   b. **native-loader closure 重驗**（§8.1 指定 S2.5A 義務）：重跑 loader resolution 並 hash 外部
      shared-library bytes，等於 base manifest 的 native-loader closure；任何新路徑/變更 byte fail-closed；
   c. **startup reconcile precondition**（obligation #7 / §10.5 #39）：S2.4 的 probe/PREPARE/APPLY journal
      無 non-terminal 殘留、無未解 `RECOVERY_REQUIRED`、install lock 無人持有；任何未解狀態 →
      `S2_4_RECOVERY_UNRESOLVED`，不 start；
   d. S2.5 自己的 start journal（§5.7）以 §5.2-同款 WAL 語義先寫 `APPLYING` 再動 effect。
2. **effect**：`systemctl enable --now arcane-equilibrium-aiml-engine-scanner.service`（typed driver 的唯一
   start 動詞；driver 不接受 caller 提供的 unit 名/參數，unit 名是模組常量）。
3. **initial running attestation** = 沿 `expected_identity_receipt_v1.running_attested` 的**五維**逐維觀測
   （這五維是 S2.3 留下的、`observation_owner==S2.5_LR6` 指定由本 session 開始擁有的觀測面）：
   - `unit`：`ActiveState=active`、`SubState=running`、`UnitFileState=enabled`、`MainPID>0`、
     `NRestarts` 基線記錄、fragment digest 不變；
   - `pid_cgroup`：MainPID 的 cmdline == §8.3 rendered argv（經 WP3 C1 指紋對齊後的版本）、cgroup ==
     unit 自己的 cgroup、boot_id+start_ticks 釘住 instance；
   - `mount`：`ExecStart` 解析自 `/opt/.../launches/<launch_bundle_digest>/`、`sys.prefix` 閉包在
     prepared tree 內（以 loader-closure 重驗 + `/proc/P/maps` 中可執行 mapping 全部落在 manifest 內表達）；
   - `network`：`RestrictAddressFamilies`/`IPAddressAllow=127.0.0.1/32` 生效、監聽面為空、唯一外連是
     loopback:5432；
   - `pg_identity`：經 **S2.0 observer role 唯讀**觀測——`alr_event_consumer_v1` advisory lock 恰被一個
     backend 持有、該 backend 是 `aiml_engine_scanner`@`trading_ai`、`learning.alr_consumer_events` 出現
     本次 `SESSION_STARTED` 且無懸掛 unclosed session、topology-guard 一致。
4. **enabled/reboot persistence**：`UnitFileState=enabled` + `WantedBy=multi-user.target` link 存在。真實
   reboot 存活證明屬 effect 面（source lane 誠實記為 `reboot_survival_observed:false`）。
5. **失敗即 rollback-to-disabled**（§8.3 末段）：start 失敗或 attestation 任何一維 fail → `stop` +
   `disable` + 驗證回到 S2.4 的 loaded/disabled/inactive 前態 → `s2_5_rollback_drill_receipt_v1(kind=
   ROLLBACK_TO_DISABLED)`。不可把部分啟動態留在機上。

**S2.5B（post-drill final attestation + watchdog reset last）**：

1. precheck：`S2.1@EFFECT_DONE` 的 `quiesce_result_v1(status=QUIESCED_STATIC_GUARDS_HELD…)` effect receipt
   digest 在手（drill 真的發生過且 restore 成功）；
2. **final running attestation**：同樣五維再證一次（drill 之後 owner 是新 PID/InvocationID，須匹配的是
   stable identity：unit+cmdline+cgroup+env-hash+digest+advisory-lock 單一持有——S2.1 §4 restoration 同款）；
3. **watchdog reset last**（`WATCHDOG_ROLLBACK_TEST` 的核心，語義沿 S2.1 §5 "watchdog-last" 謂詞）：
   最後一個 lifecycle 操作是本 phase 自己的 recovery-machinery reset（`systemctl reset-failed` + `NRestarts`
   基線歸零記錄），且 typed `watchdog_last` 區塊證明「最後一次 lifecycle transition == 已授權操作本身、
   期間無 supervening/unexplained restart」。放在**最後**的理由：reset 之後任何新 restart 都無法再被
   歸因於 drill/start 噪音，dead-man 觀測（LR6/S3.4 接手）從乾淨基線起算。當前 unit 無 `WatchdogSec`，
   liveness 是 `Restart=on-failure` 機制——`watchdog_last.watchdog_usec` 誠實記 `none`（S2.1 §5 同款），
   本設計不擅自加 `WatchdogSec`（改 unit 是 S2.4 renderer 的 owned 面；O-2）；
4. **observer/dead-man gate**（兩個 attestation 共用的 closed 子物件，§5.4）：attestation 的每一維證據
   必須由 **applier 以外的 verifier node** 在 `max_evidence_age_seconds` 內採集（dead-man 語義：證據缺席
   或過期 = fail，不存在 green-by-default）；DB 維度只能經 S2.0 observer role。

### 5.1 `s2_5_start_core_v1`（unsigned core）+ `s2_5_start_intent_v1`

core（被簽物，排除 ID/授權/self_digest）：
`schema_version`(const) · `phase`(enum `S2_5A_START|S2_5B_FINAL`) · `target_host` ·
`unit_name`(const `arcane-equilibrium-aiml-engine-scanner.service`) ·
`expected_unit_fragment_digest` · `s2_4_install_effect_receipt_digest` ·
`expected_launch_bundle_digest` · `expected_application_bundle_digest` ·
`expected_base_runtime_tree_digest` · `native_loader_closure_digest` ·
`s2_1_drill_receipt_digest`(digest|null；`S2_5B_FINAL` 必非 null，`S2_5A_START` 必 null) ·
`attestation_window`{`max_evidence_age_seconds`,`min_samples`,`sample_interval_seconds`} ·
`start_budget_seconds` · `rollback_budget_seconds` · `safety_margin_seconds` ·
`authorization_profile_ids`(closed 枚舉，§5.6 的 profile id；只宣告 profile/max-TTL policy，**不含**任何
authorization 物件/digest/簽章) · `source_head` · `issued_at` · `expires_at`。

派生：`start_core_digest = digest(core)`；`start_id = "s2-5-" + hex(start_core_digest)`；
intent = `{core, core_digest, derived_id, self_digest}`，validator 獨立重導出每一欄（S2.4 §5.1 同款，
無 digest/signature cycle）。`FORBIDDEN_INTENT_KEYS`：任何 raw command / unit text / `signal` / `pid` /
`kill` / caller-supplied 路徑鍵直接拒絕。

  const false；production 由 attestor 簽章的觀測才可 true)} ·
`observer_gate`(§5.4) · `precheck`{inactive_prestate_verified,loader_closure_reverified,
  s2_4_recovery_clear,install_lock_free}(全 bool) ·
`rollback_record`(embedded §5.5 之 5.3 | null) · `apply_actor_node` · `independent_verifier_node`(≠ applier) ·

`evidence_class`(enum `LOCAL_REPRODUCIBLE|STRUCTURAL_ONLY|PLATFORM_OR_EXTERNAL_ATTESTED`) ·
`boundary`{**production_started_by_source_lane:false** · **production_running_attested_without_attestor:false**

`started_at` · `completed_at` · `evidence_expires_at` · `failure_reason`(str|null) · `source_head` ·
`self_digest`。
`allOf`：`status==RUNNING_ATTESTED ⇒ target_class==production && trusted_host_attestation 非 null 且驗簽
資訊齊備 && 五維全 pass && evidence_class==PLATFORM_OR_EXTERNAL_ATTESTED`；
`status==SOURCE_SIMULATION_PASS ⇒ target_class∈{simulated_harness,disposable_local} &&
trusted_host_attestation==null && evidence_class==LOCAL_REPRODUCIBLE`；
`status==EXTERNAL_VERIFICATION_PENDING ⇒ 觀測欄空/預設 && failure_reason 說明缺口`。

### 5.3 `s2_5_rollback_drill_receipt_v1`

`schema_version`(const) · `kind`(enum `ROLLBACK_TO_DISABLED|WATCHDOG_RESET_LAST`) · `status`(enum
`RESTORED_INACTIVE|RESET_CLEAN|NOT_RESTORED|FAILED`) · `intent_id` · `unit_name`(const) ·
`pre_state`{active_state,unit_file_state,n_restarts,invocation_id} ·
`post_state`{同構} · `operation`(structured，如 `{"kind":"systemd_stop_disable"}` 或
`{"kind":"systemd_reset_failed"}`——非 raw command string；S2.1 §7.4 同款) ·
`s2_4_inactive_prestate_digest`(rollback-to-disabled 必須綁 S2.4 receipt 所證的 inactive 前態) ·
`watchdog_last`(§5.4；`kind==WATCHDOG_RESET_LAST` 必非 null) · `observed_at` · `expires_at` ·
`source_head` · `self_digest`。
`allOf`：`RESTORED_INACTIVE ⇒ post_state=={inactive,disabled} 且與 s2_4 前態 stable-identity 相等`；
`RESET_CLEAN ⇒ watchdog_last.unexplained_restart_detected==false && post_state.n_restarts==0`。

### 5.4 共用 closed 子物件：`watchdog_last` 與 `observer_gate`

**PM 裁決（2026-07-28，option (b)）：** 不獨立成 schema、不跨檔 `$ref`；`watchdog_last` 與
`observer_gate` 在需要它們的每一份 schema 內**各自完整寫出欄位**（closed、
`additionalProperties:false`），並允許按 phase 語義微分（例如 final attestation 的
`watchdog_last` 綁 reset-last 謂詞，rollback receipt 內的同名塊綁 drill 操作本身）。**不**發明
byte-level 同構測試釘兩份不漂移——語義微分是被允許的，byte 同構測試會把它禁掉；也**不**選
phase-discriminator 單一 schema，因為兩個 attestation artifact 有不同的下游消費者

## §8 Fixtures / tests 策略

### 8.1 三態 lifecycle fixtures（#29 第二子句的 source 表達）

`_simulated_unit(tmp_path)`：一個受控 unit 狀態機 harness——注入 `systemctl show` property dict + 注入
driver（`enable_now` 把 `{UnitFileState:disabled, ActiveState:inactive}` 翻成
`{enabled, active/running, MainPID>0, InvocationID}` 並掛出 temp `/proc/<pid>` 樹；`stop`+`disable` 反向；
`reset_failed` 歸零 `NRestarts`）。真實主機零接觸。fixtures 逐一覆蓋：

1. **`enable --now`**：happy path 全鏈 precheck→enable→五維觀測→`SOURCE_SIMULATION_PASS`；
2. **enabled / reboot-persistence**：`UnitFileState=enabled` + wanted-by link 斷言；harness「重啟 manager」
   後 unit 仍 enabled（persistence 的 source 可證半邊；真 reboot 存活誠實留 effect）；
3. **running**：五維各自的失敗注入（disabled 未翻、MainPID=0、cmdline 替身、cgroup 外進程、loader 閉包外
   mapping、監聽 socket 出現、advisory lock 雙持有/零持有、unclosed session 懸掛）→ 對應維 fail ⇒ 整份
   attestation 非 PASS；
4. **rollback-to-disabled**：start 失敗/attestation 失敗兩路都必須產出
   `s2_5_rollback_drill_receipt_v1(RESTORED_INACTIVE)` 且 post_state 等於 S2.4 inactive 前態；rollback 自身
   失敗 → `NOT_RESTORED` 誠實失敗，絕不轉成功；
5. **watchdog reset last**：`reset_failed` 之後注入一次 supervening restart ⇒
   `unexplained_restart_detected` 使 `RESET_CLEAN` 不可達。

### 8.2 fail-closed / 授權面

- `driver is None` → `EXTERNAL_VERIFICATION_PENDING`，零變更、零 driver 呼叫（斷言 mock driver 未被觸碰）；
- `target_class=production` + 有效 permit + 無 attestor → 永不產生 attested status；
- namespace 域分離：S2.0/S2.1/S2.4 任一 namespace 的簽章重放為 S2.5 permit/attestor → 拒；payload 任一欄
  竄改 → 拒；過期/skew 越界 → 拒；replay ledger 重複消費 → `AUTHORIZATION_REJECTED`；
- `S2_5B` intent 缺 `s2_1_drill_receipt_digest` → schema 直接拒；S2.5A intent 帶了它也拒（相互 const）。

### 8.3 disposable 證據與 platform-attested 證據的分界（硬邊界測試）

- 任何 fixture 產物 `evidence_class` 只能是 `LOCAL_REPRODUCIBLE`/`STRUCTURAL_ONLY`；一支測試專門構造
  「fixture 偽裝 `PLATFORM_OR_EXTERNAL_ATTESTED` + 偽 attestor 物件」並斷言 validator 拒絕（缺真簽章、
  fingerprint 不符、namespace 不符三路各一）；
- `boundary.fixture_impersonates_platform_attested` const false：schema 級把「假冒」做成不可表達；
- disposable-PG lane 沿 S2.0/S2.1 的 `shutil.which("initdb")`+psycopg2 skip gate；skip 不計入 coverage
  （W5 先例：跳過的 probe 測試不是覆蓋）。

### 8.4 E4 mutation 面（每一刀必須讓至少一支測試變紅）

刪 precheck 的 `S2.4-receipt 綁定` 呼叫；刪 loader-closure 重驗；刪 `s2_4_recovery_clear` 檢查；把
observer_gate 的 `stale` 判斷改為默認 fresh；把 `watchdog_last` 的 supervening-restart 檢查短路；

## §12 誠實邊界（source seam 證不了什麼；EFFECT 何時可宣告）

**本 seam 證不了 running。** simulated harness 的 `SOURCE_SIMULATION_PASS` 只證「狀態機與守衛邏輯在注入
環境下正確」；disposable-PG 的 observer 讀證「證據在最小權限下可觀測」；兩者都不是 unit 真的 enabled、
進程真的活著、PG identity 真的匹配。`LOCAL_REPRODUCIBLE` 自證 integrity，永不自證 execution（W5
`EMITTED_EVIDENCE_DIGESTS_ARE_UNAUTHENTICATED` 的同一結構性邊界）。

**`S2.5A@EFFECT_DONE`（running_attested）可宣告當且僅當**：`S2.0@EFFECT_DONE` 與
`S2.4@EFFECT_DONE_INACTIVE`（含 S2.4-AMEND-1/AMEND-2 落地）都真實發生；fresh S2.5A start permit 簽發並
消費；governed Linux driver 在 exact head 執行 `enable --now`；五維觀測由獨立 verifier 採集且
observer/dead-man gate fresh；trusted-host attestor 簽出 exact-intent-bound attestation 並驗簽通過；
journal terminal、無 recovery 殘留。**`S2.5B@EFFECT_DONE` 另需**：`S2.1@EFFECT_DONE`（其前置
`WP3_INVOCATION_FINGERPRINT_ALIGNMENT_REQUIRED` 已由 W2 renderer + WP3 fingerprint amendment 解除——
此項不歸 WP5 修，歸 S2.1 EFFECT session 前的 WP3 amendment）；post-drill 五維再證；watchdog reset
**last** 且 `RESET_CLEAN`。兩個 phase 的失敗路徑都必須留下 rollback receipt 或 typed
`RECOVERY_REQUIRED`，絕不把部分態轉成功。

**S2.5 之後仍未證的**：長時 liveness/SLO/dead-man 常駐觀測（LR6=S3.4）、ingestion 相容 runtime 驗證
（S2.2B）、任何 profitability/trading 效果（永不屬本 program 的 S2）。
